## [重，霸榜中] Nv-embed: Improved techniques for training llms as generalist embedding models

> [https://arxiv.org/pdf/2405.17428](https://arxiv.org/pdf/2405.17428)

-   该研究介绍了一种名为 NV-Embed 的模型，旨在提高大型语言模型（LLM）作为通用文本嵌入模型的性能。本论文通过

-   在对比学习中去除解码器 LLM 的因果注意力掩码，以增强模型的表示能力（单向变双向）
-   提出了一种新的池化技术，通过潜在的注意力层（训练了一个 K 和V，对于 LLM 输出的向量 Q 再计算一下，送入 MLP +GELU，取平均池化作为最终输出）来获得更富有表现力的序列池化
-   两阶段指令调整：首先在检索数据集上进行对比训练（in-batch 负样本和挖掘出来的负样本），然后在非检索数据集上进行第二阶段训练（不再用in-batch 负样本了），以提升模型在多种任务上的性能。

-   这种训练设计的目的在于研究人员认为检索任务比其他任务更难，所以训练策略一开始需要先聚集在提升模型在检索任务上的性能

-   使用LoRA方法来高效微调 NV-Embed 模型
-   输入数据拼接：![image.png](/img/yuque/计算机/深度学习/Embedding/assets/大模型_TextEmbedding-8.png)
-   消融实验的结果

-   ![image.png](/img/yuque/计算机/深度学习/Embedding/assets/大模型_TextEmbedding-9.png)

-   hard 样本是怎么挖掘的？

-   排序在非第一位的样本，并且BM25 分数大于 2.5 的（有较高相关性，但实际是负样本）

-   使用秩为16的LoRA（低秩适应），α值为32，以及0.1的dropout率。我们使用Adam优化器，第一阶段有500个预热步骤，学习率为2e-5，第二阶段学习率为1.5e-5，并采用线性衰减。模型微调时使用128的批量大小，每个批次由一个查询配对1个正面样本和7个硬负样本组成。我们使用Bfloat16进行训练，并设置最大序列长度为512个标记。在给定的查询和文档的开始和结束处分别附加特殊的<BOS>和<EOS>标记。
-   为什么论文认为 EOS 的效果不好？

-   最近偏差（Recency Bias）：<EOS>标记的嵌入可能会受到最近偏差的影响，这意味着模型在生成嵌入时可能会过分依赖于序列中最后几个标记的信息。这可能导致嵌入不能很好地捕捉到整个输入序列的关键信息，特别是如果关键信息出现在序列的早期部分。
-   不足以表示复杂语义：对于复杂的语义任务，仅使用<EOS>标记可能不足以捕捉输入文本的全部语义信息。这是因为<EOS>标记的嵌入可能无法有效地聚合整个序列的信息，特别是在处理长文本或需要理解全文上下文的任务中。
-   与序列其他部分的脱节：如果<EOS>标记的嵌入不能很好地与序列的其他部分的表示相结合，那么生成的嵌入可能无法准确地表示整个序列的语义内容。

## [重] LLM2Vec: Large Language Models Are Secretly Powerful Text Encoders

> [https://arxiv.org/pdf/2404.05961](https://arxiv.org/pdf/2404.05961)

LM2Vec，这是一个简单的无监督方法，可以将任何仅解码器的大型语言模型（LLM）转换为强大的文本编码器。

-   LLM2Vec 包括三个步骤：启用双向注意力、掩码下一个词预测和无监督对比学习。
-   在单词级别的任务上，LLM2Vec 转换的模型大幅超越了仅编码器的模型，并在 Massive Text Embeddings Benchmark (MTEB) 上达到了新的无监督状态最先进的性能。

具体方案：

-   **启用双向注意力**：通过替换因果注意力掩码为全一矩阵，使每个 token 能够访问序列中的所有其他 token。

-   在标准的解码器型LLMs（如GPT系列模型）中，因果注意力掩码（causal attention mask）确保在处理序列中的每个位置时，模型只能看到它之前的位置，而不能访问之后的位置。这种掩码通常是一个上三角矩阵，其中对角线以上的元素被设置为负无穷大（或其他一个足够大的负数），以确保在softmax操作中这些位置的权重为零。
-   为了使LLMs能够进行双向注意力计算，需要将这种因果注意力掩码替换为全一矩阵。全一矩阵意味着矩阵中的所有元素都是1，没有任何限制，这允许模型在处理任何一个位置时都能访问序列中的所有其他位置。除了修改掩码外，模型的其他部分（如前馈网络、层归一化等）保持不变。

-   **掩码下一个词预测（MNTP）**：结合下一个词预测和掩码语言建模的训练目标，使模型能够基于前后文预测掩码 token。

-   **选择掩码比例**：首先确定需要被掩码的token的比例。例如，可以选择掩码输入序列中15%的token，这个比例可以根据具体任务和模型进行调整。随机选择一定比例的token并将它们替换为特殊的[MASK] token，这些token将被模型预测。
-   在预测被掩码的token时，模型需要利用其双向注意力机制来同时考虑前面的和后面的上下文信息。对于每个被掩码的token，模型会基于其上下文（包括被掩码token前后的token）来预测其原始值。损失函数通常采用交叉熵损失，比较模型预测的分布和真实token的分布。对于每个被掩码的token，使用其前一个token（或特殊标记，如[BOS]，即句子开始标记）的表示来计算预测的logits，然后计算交叉熵损失。

-   **无监督对比学习**：通过 SimCSE 方法，使用不同的dropout掩码生成同一句子的两个不同表示，并训练模型最大化这两个表示的相似性，同时最小化与其他句子表示的相似性。

![image.png](/img/yuque/计算机/深度学习/Embedding/assets/大模型_TextEmbedding-10.png)

实验结果

-   在word-level的任务上（比如NER，POS等任务，模型先获得文本的表征，然后再过一层需要进一步训练的线性分类层），LLM2Vec都取得明显提升，**但是进一步的无监督对比学习训练并没能进一步提升模型性能，研究人员认为这是因为这类任务更多关注的是token本身的表征，而非句子整体的信息，所以只进行了MNTP就能取得不错效果。**

-   ![image.png](/img/yuque/计算机/深度学习/Embedding/assets/大模型_TextEmbedding-11.png)

-   **而对于更关注句子整体表征的MTEB任务中，LLM2Vec取得巨大提升，并且可以看到第三步对比学习的加入进一步提升了效果。**

## Llama2vec: Unsupervised adaptation of large language models for dense retrieval

> [https://aclanthology.org/2024.acl-long.191/](https://aclanthology.org/2024.acl-long.191/)

​  

这篇论文提出了一种新方法，名为Llama2Vec，用于无监督地适配大型语言模型（LLMs），以便在密集检索（Dense Retrieval）任务中使用。密集检索需要能够区分查询和文档之间语义关系的嵌入表示。Llama2Vec包含两个预文本任务：基于嵌入的自编码（EBAE）和基于嵌入的自回归（EBAR）。这些任务促使LLM根据文本嵌入重构输入句子和预测下一句。Llama2Vec简单、轻量但高效，通过在Wikipedia语料库上适配LLaMA-2-7B模型，显著提高了模型在多个密集检索基准测试中的微调性能，特别是在MSMARCO的段落和文档检索以及BEIR的零样本检索上达到了新的最佳性能。

-   **预文本任务**：Llama2Vec包含两个预文本任务，EBAE和EBAR。EBAE任务中LLM被提示生成输入句子的归纳文本嵌入，而EBAR任务中LLM被提示生成下一句的演绎文本嵌入。

-   **基于嵌入的自编码（EBAE, Embedding-Based Auto-Encoding）**：

-   **目的**：EBAE任务旨在让LLM学习生成能够表示输入句子本身的全局语义的嵌入向量。
-   **操作**：在这个任务中，**LLM被提示生成输入句子的归纳文本嵌入**。这意味着模型需要利用输入句子的文本嵌入来预测句子中词汇的分布。通过这种方式，模型学习到的嵌入能够捕捉到输入句子的整体语义特征。
-   **提示模板**：`[Placeholder for input] SELF ⟨\s⟩`，其中`SELF`代表EBAE的提示，即“输入句子是：”。

-   **基于嵌入的自回归（EBAR, Embedding-Based Auto-Regression）**：

-   **目的**：EBAR任务旨在让LLM学习生成能够表示与输入句子相关联的下一句的全局语义的嵌入向量。
-   **操作**：在这个任务中，**LLM被提示生成下一句的演绎文本嵌入**。模型需要利用输入句子的文本嵌入来预测下一句中词汇的分布。这有助于模型学习到的嵌入能够捕捉到输入句子与下一句之间的语义关联。
-   **提示模板**：`[Placeholder for input] NEXT ⟨\s⟩`，其中`NEXT`代表EBAR的提示，即“下一句是：”。

-   损失hanshishuai是交叉熵损失函数来最小化预测分布和实际词汇ID之间的差异。

## Improving Text Embeddings with Large Language Models

> [https://arxiv.org/pdf/2401.00368](https://arxiv.org/pdf/2401.00368)

作者对检索任务进行了分类，并根据分类让大模型生成训练样本（从零开始生成。。。）

-   Asymmetric Tasks非对称任务：两边文本相关，但是语义不一定完全一致，可能是存在一些隐含的关系。例如：搜索引擎query-doc两边信息肯定不一样，但是是相关的

-   按照两边长度对比分为了：short-long match, long-short match, short-short match, and long-long match。然后让大模型对每个组 brainstorm a list of tasks，并结合任务定义给出一个具体的例子
-   数据生成流程是，第一步，作者给出一个任务组的大致范围和约束，然后让大模型自己去想一系列检索的任务，包括科研论文检索/财报检索/图书检索，总之各种任务都可以，随意brainstorm。然后第二步，再让大模型自己去对刚刚自己生成的任务定义，去编一个具体的例子，包括query和正样本以及负样本。
-   ![image.png](/img/yuque/计算机/深度学习/Embedding/assets/大模型_TextEmbedding-15.png)

-   Symmetric Tasks对称任务：两边文本语义也很对称/类似。

-   直接定义prompt去生成数据

生成完样本后，就可以送入 Mistral-7B 进行训练了。

-   训练时的输入

-   query 侧输入是 Instruct: {task\_definition} \\n Query: {query}
-   doc 侧输入是文档本身，不加 prompt

-   在 query 和 doc 后，拼接了 [EOS] 符号，打包送给大模型获取[EOS] 的向量表示作为整体文本表示
-   loss 用的是 InfoNCE Loss，batch 内负采样

## Fine-Tuning LLaMA for Multi-Stage Text Retrieval

> [https://arxiv.org/pdf/2310.08319](https://arxiv.org/pdf/2310.08319)

研究通过对最新的LLaMA模型进行微调，分别作为密集检索器（RepLLaMA）和点对点重排器（RankLLaMA），在MS MARCO数据集上进行实验。

-   研究发现，LLaMA模型在处理长文本时表现优于小型模型，能够整体表示整个文档，避免传统的分段和汇聚策略。
-   RepLLaMA：是作为密集检索器（dense retriever）进行训练的，其训练方法遵循双编码器（bi-encoder）架构，以下是具体的训练细节：

-   目标是找到与查询最相关的 k 个文档
-   query 和 doc 分别编码得到向量，然后计算相关性
-   骨干模型初始化为 LLaMA2-7B，一个基于Transformer架构的自回归、仅解码器的大型语言模型。
-   由于 LLaMA 是单向的，将查询或文档的序列附加结束序列标记 `</s>` 作为输入。计算输入序列的向量嵌入 VT 为 LLaMA 模型的最后一个层的token表示
-   损失函数是 InfoNCE loss
-   hard 负样本从现有检索系统的最高排名结果中采样，以及从同一批次中其他查询的正样本和硬负样本衍生出来的负样本（in-batch negatives）。
-   其他结论：

-   全微调和参数高效方法的比较：在全微调（Full Fine-Tuning）和参数高效方法（如LoRA）之间，LoRA在独立人类判断的数据集上展现出更好的效果，这表明全微调可能在训练集分布上过拟合，而参数高效方法有更好的泛化能力。
-   输入序列长度的影响：通过改变输入序列长度对RankLLaMA性能的影响实验，发现模型的有效性随着训练输入长度的增加而提高，但也存在收益递减的点，需要在模型性能和计算效率之间找到平衡。
-   模型大小的影响：实验结果还表明，增加模型大小（例如，从7B到13B参数）可以进一步提升检索效果，这表明模型规模的扩大有潜力进一步提升性能。
