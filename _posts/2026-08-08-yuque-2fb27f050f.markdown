# 背景

为什么做这个？

美团大搜供给类型多，业务错综复杂，但用户的 query 平均长度又很短，因此有很多中长尾 query 的意图是不明确的（意图错误占客诉比例100%，影响较为恶劣，会导致正常商家无召回或召回排序靠后）

设计成 RAG 任务，和 where-what 那个 merge 成一个

# 目前地址意图判断有哪些方案，为什么要用大模型？

目前意图判别是高频词表 + 中长尾 BERT 模型做的。其中：

-   高频词表是出版运营标注的，流量占比在TOP 60% 的各业务顶流数据

-   后续维护是每日自动生产，变化部分交由外包抽样标注的

-   BERT 模型：

-   采用 MTBERT 作为基座模型，特征包含XXX，详见地标业务消岐模块

BERT 模型对中长尾的准召率指标还可以，但对于长尾部分 query 效果一般，原因是模型缺乏足够的世界知识来辅助判别。如 桔子里，BERT 模型倾向于认为是商品，但实际上是一个住宅小区，大模型可以轻松应对，甚至还能告诉橘子洲的存在。

# 实现方案

## 候选 query 挖掘

-   与团好货、优选的意图冲突词作为候选
-   在全国多个城市有搜索但没有识别到地标，但仔少数城市识别到地标的 query 和具体城市信息
-   session 内高换词率，换词前是地标，换此后不是地标，且换词前后文本重叠占比较高的

上面三个非地标误识别为地标的概率较高。

为什么不做地标被识别到非地标的检验？1. case 较少，且文本召回能满足基本需求，不太恶劣。2. 正常地标石碑优化会扩召回，提升地标覆盖率。

最终通过上面三种类型，得到初始候选数据 80w query

## prompt 编写

```json
现在请你扮演一个地标判别器，功能是判别用户给的查询词是否包含地址成分，地址成分的定义是现实世界的地理空间位置，一个地址成分代表一个地理位置。地址成分一般有商场、景点、行政区、商圈、运动场馆、地铁线、商务楼、小区、交通站点（火车站、飞机场、公交站、地铁站等）、教育院校（幼儿园、小学、中学、大学、大专、职业学院等）、医院、政府机构、公司企业、交叉路口、道路名、门牌号、单元号等类型。明确不属于地址成分的类型比如商品、药品、货物、美妆、食品等类型。举几个例子，例子1：查询词是 "罗文市场" ，从查询词本身上看，以及常识推断，该查询词包含地址成分，因为它确实对应了实际地理位置-市场；例子2 查询词是 "奥特莱斯" ，以及常识推断，该查询词包含地址成分，因为它确实对应了实际地理位置-商场；例子3 查询词是 "应急电源" ，以及常识推断，该查询词不包含地址成分，因为它实际是一个商品，不是一个地理位置；例子4 查询词是 "视频赚" ，从查询词本身上看，以及常识推断，该查询词不包含地址成分，因为它实际是一个APP里面的产品，不是一个地理位置；现在结合上面几个例子，请判断查询词 "假草坪" 是否包含地址成分？
```

## 效果评估

采用抽样方式进行评估，准确率为 93.4%。符合上线要求。初始挖掘得到误识别 query 20w+，日均影响 QV 60w+（0.84%），，后续每日更新约 7K 条

## 最终上线方案与收益

上线方案是收集当前疑似 query ，离线调用 ChatGPT 模型进行挖掘，将识别结果存储到 hive 表中，最终同步到线上意图词表中。
