# 高质量数据筛选

## 总览

1.  么算是高质量微调数据？

1.  多样性高的

1.  涵盖多种类别的数据
2.  每种类别有多种不同的表达、模式

2.  数据质量：准确性要有保证
3.  数量：每种类别的数据量不能太少，对于 LLM 来说，如果任务和 LLM 的知识分布差别不大的话，几百条就够了，差别很大的话就要看情况增加，甚至继续预训练
4.  难度分配合理（简单、中等、难都有）
5.  必要性：指令数据能填充 LLM 的能力缺口，不能训了跟没训一样（和难度类似？）

2.  怎么评估数据的多样性？或者说怎么从大量数据里选出高质量的多样性高的数据？

1.  k-means 方法进行聚类，从聚类的每一个簇中采样，生成100个样本作为初始的模型
2.  k-center贪婪算法从数据中选择出最远的k个中心点，保证覆盖率（k-center 的近似算法是首先选择一个点作为第一个中心，然后每次选择离当前已选中心集合最远的那个点作为下一个中心，直到选择出 k 个中心。）(Superfiltering: Weak-to-Strong Data Filtering for Fast Instruction-Tuning)

3.  怎么评估数据的必要性？或者说获得必要性高的数据？

1.  方法1，用第三方奖励模型找到表现差的，做针对性增强(MoDS: Model-oriented Data Selection for Instruction Tuning)

1.  用初始选出来的数据集训练模型，然后让模型对高质量数据集中的指令进行数据生成
2.  用 reward-model-deberta-v3 对指令数据进行评估，得到的分差的指令数据

1.  它是基于 DeBERTa 架构设计的奖励模型，并在四种不同类型的人类反馈数据上进行训练，赋予其QA模型评估、奖励评分和通过排名检测潜在毒性反应的能力。

3.  取和得分差的指令类似的指令数据作为补充，来提升模型能力

2.  方法2：用 one-shot 方法，把指令数据挨个作为 ICL 对测试样本进行输出，通过对输出进行评估找到能使得输出loss 降低的指令样本作为最终训练样本（这不算泄露？）（Nuggets：One Shot Learning as Instruction Data Prospector for Large Language Models）
3.  方法3：比3.2 更狠， 选择那些对测试集loss 下降最大的那些训练数据

4.  怎么评估数据质量？

1.  利用ChatGPT直接评估对特定指令输出结果的准确性
2.  人工抽样评

5.  怎么评估数据的难度？

1.  IFD(Instruction-Following Difficulty)：有输入 Q 情况下生成 A 的似然均值 除以没有 Q 情况下输出的似然均值。高 IFD 说明问题难度高。（可以利用大模型和小模型间的一致性（毕竟都是语言模型，对于通用任务的偏好还是类似的），使用小语言模型来评估似然值）(IFD : From Quantity to Quality: Boosting LLM Performance with Self-Guided Data Selection for Instruction Tuning)
2.  Instag Complexity：利用ChatGPT对部分数据进行打标签，再训练一个Llama模型，再利用训练后的Llama模型对全量数据预测，标签越多说明数据约复杂。
3.  Instruction Length：按照指令的长度计算复杂性。
4.  Instag Complexity：利用ChatGPT对部分数据进行打标签，再训练一个Llama模型，再利用训练后的Llama模型对全量数据预测，标签越多说明数据约复杂。
5.  Perplexity：通过预训练模型计算回复的困惑度作为复杂性指标，困惑值越大意味着数据样本越难。

## 论文

### LIMA: Less Is More for Alignment

> [LIMA: Less Is More for Alignment](https://arxiv.org/abs/2305.11206)

在人工设计的指令调优的数据上微调一个语言模型，并且实验结果证明相比于数量，高质量数据对于模型微调的重要性更大。**对于给定的训练充分的语言模型（多充分？作者是 65B LLaMA），通过1000个精心构建的训练实例进行简单的微调，就可以获得非常强的性能。**

利用的假设是：**浅层对齐假设(**Superficial Alignment Hypothesis)，模型的知识和能力几乎完全是在预训练过程中学习到的，而对齐工作则是使模型学习到怎样和用户进行交互，将模型在预训练阶段内部存储的知识表现出来。

实验结果表明，LIMA的训练方式比Alpaca的效果更好，而后者的数据量则是前者的52倍。 相比于其他商用的模型(DaVinci003, BARD, Claude)，LIMA与其也是互有优劣。

什么样的数据算高质量数据？

-   多样性：越高越好 wikiHow(低多样性) VS Filtered Stack Exchange（高多样性）
-   质量：Filtered以及Unfiltered的Stack Exchange的训练结果进行对比，表明了训练质量的重要性。
-   数量：从Stack Exchange中进行采样，然后进行训练。图6表示，在没有增加数据多样性和质量的前提下，盲目的增加数据量对于模型性能的提升可以忽略不记，甚至是有害的。（2k->32K 没啥提升，甚至下降了些）

### Superfiltering: Weak-to-Strong Data Filtering for Fast Instruction-Tuning

> [Superfiltering: Weak-to-Strong Data Filtering for Fast Instruction-Tuning](https://arxiv.org/abs/2402.00530)

24 年2月。采用一个更小的模型来选择数据，进而微调一个更大的，更强的模型。

上面的方案虽然有效，但是用大模型多轮选数据太浪费了。所以这里用一个更小的模型（多小算小？）来选择数据，来微调大模型。

前提假设是尽管弱语言模型和强语言模型之间存在性能差距，但是作者发现它们之间存在高度一致的感知教学难度和数据选择结果的能力，具体的表现为IFD分数和困惑度的排序高度一致性。这使得作者可以采用更小的，更高效的模型来过滤与用于训练LLM的指令数据。

在评价弱模型和强模型一致性的方面，作者采用Spearman秩相关系数(Spearman秩相关系数是一种非参数的相关性度量，用于评估两个变量的相关性，即它们是否随着对方的增加或减少而单调地变化)来评估相关性。从图中可以看出，即使是GPT-2模型，也和Llama2-7B模型的秩相关系数保持在0.7左右，并且筛选出来的数据集之间存在一定的重叠，这表明弱模型和强模型之间可能存在一定的一致性。

base 是 LLaMA2-7B ，小模型是从 GPT-2 到 GPT-NEO，确实是个思路，小模型选数据。模型规模方面，可以看到大概的趋势，模型规模变大，对应的数据质量越高，训练得到的模型性能越强。

### MoDS: Model-oriented Data Selection for Instruction Tuning

> [MoDS: Model-oriented Data Selection for Instruction Tuning](https://arxiv.org/abs/2311.15653)

23年11月。提出新的指令数据选择标准：质量，覆盖率和必要性，提出一种新的数据选择流程。

-   质量：所有选择的指令数据的问题和答案对足够好
-   覆盖率：指令数据足够多样
-   必要性：求指令数据填补了LLM的能力缺口

该方法有三个阶段：

-   第一阶段采用质量评估模型(reward-model-deberta-v3)对所有指令数据进行评估。

-   它是基于 DeBERTa 架构设计的奖励模型，并在四种不同类型的人类反馈数据上进行训练，赋予其QA模型评估、奖励评分和通过排名检测潜在毒性反应的能力。

-   第二阶段通过k-center算法(k-center贪婪算法从数据中选择出最远的k个中心点，保证覆盖率)，从高质量的数据中选择种子数据集。
-   基于模型自身的特性进行选择，选择出必要的数据作为增强数据集。

-   怎么选：用选出来的初始数据集训练模型，然后让模型对高质量数据集中的指令进行数据生成，之后用必要性评估模型（第一部分的奖励模型）来计算每条指令和它生成的分数，分数小于阈值那就是这类指令能力处理差，差的话就重复第二步补充下数据，依次循环。

### CAR：Clustering and Ranking: Diversity-preserved Instruction Selection through Expert-aligned Quality Estimation

> [https://arxiv.org/pdf/2402.18191](https://arxiv.org/pdf/2402.18191)

同 MoDs 的方法十分相似，但流程更为简洁。该方法融合了质量和多样性两个关键要素。首先，它使用评分模型对数据进行质量评估，筛选出高质量数据作为训练集的一部分。为了保持数据的多样性，还采用k-means聚类，并从每个簇中选取高质量数据，作为训练数据的另外一部分。最终筛选出来的数据同时兼顾质量和多样性。

![image.png](/img/yuque/计算机/大模型/2._模型微调及使用方式调研/assets/指令微调如何获取高质量数据-6.png)

-   评估模型是啥？

-   Instruction pair Quality Scoring模型 IQS，使用了Comet框架中的Sentence BERT作为基础，并直接将指令对的不同部分通过空格连接起来进行训练。训练数据来自专家修订的数据集，该数据集包含了对Alpaca\_52k数据集中3,751个指令对进行改进的版本。这些改进旨在提高指令的流畅性和准确性，减少歧义，并提高问题和回答之间的语义一致性。准确率比较高 84.5%，说明和人类偏好对齐的比较好。

### Nuggets：One Shot Learning as Instruction Data Prospector for Large Language Models

假设，现在我们有5个不同的任务场景需要优化，每个任务配有4条测试数据，共计20条测试数据。目前，我们还拥有1000条训练数据。为了评估这些数据对测试集的增益效果，我们将每条训练数据逐一作为one-shot example，观察加入其后对每条测试数据输出的影响。若加入某条训练数据能降低测试数据的损失，则视为有增益效果，可能值得加入到最终的训练集中。

​  

1.  **定义任务集（Predefined Task Set）**：首先定义一个包含多种任务的任务集，这些任务用于评估语言模型在不同任务上的性能。
2.  **计算 Zero-Shot 得分（Zero Shot Score）**：对于任务集中的每个任务，使用预训练的大型语言模型（LLM）来计算模型在没有指令调整的情况下完成任务的概率。这个概率被称为零次得分，它反映了模型在没有额外指令的情况下对任务的掌握程度。

1.  每条训练数据将根据其对20条测试数据中多少条有增益效果来获得一个得分，例如，若一条训练数据能让16条测试数据得到增益，则其得分为0.8（即16/20）。我们将根据这一得分机制，选择得分高的数据组成精选训练集。具体来讲：

3.  **计算 One-Shot 得分（One Shot Score）**：将指令数据集中的每个示例作为单次提示（one shot prompt），与任务集一起输入模型。然后，重新计算模型在这些任务上的完成水平，这被称为单次得分。
4.  **计算 Golden Score**：通过比较单次得分和零次得分的差异，为每个指令计算黄金得分。黄金得分反映了指令作为单次示例对模型性能提升的影响。
5.  **选择高黄金得分的子集**：根据黄金得分对所有指令进行排序，并选择得分最高的子集作为“黄金子集”（golden subset）。这个子集被认为是最有价值的数据，可以直接用于模型的指令调整（instruction tuning）。
6.  **指令调整和性能评估**：使用选定的黄金子集对模型进行指令调整，并在基准测试上评估调整后模型的性能。

### LESS: Selecting Influential Data for Targeted Instruction Tuning

> [https://arxiv.org/abs/2402.04333](https://arxiv.org/abs/2402.04333)

不同于 Nuggets 的是， Nuggets 是考察训练集作为 one-shot 对测试集的提升， LESS 更直接， 考察的是训练集给模型梯度优化方向对测试集loss 的下降， 选择那些对测试集loss 下降最大的那些训练集作为 gold train dataset。具体为：

1.  **预热训练（Warmup Training）**:

-   使用 LoRA（Low-Rank Adaptation）方法对预训练的基础模型进行预热训练，以减少可训练参数的数量并加速内部乘积的计算。

2.  **计算梯度特征（Compute Gradient Features）**:

-   对于验证数据点，使用 LoRA 方法计算低维梯度特征，这些特征是通过**随机投影**得到的，可以用于数据选择。
-   随机投影咋做的？构造一个随机投影矩阵，维度为 P x d，P 是 LoRA 的梯度的维度，d 是投影后的维度。根据 Johnson-Lindenstrauss引理，随机投影能够以高概率保持原始数据点之间的内积，这意味着投影后的低维特征仍然能够有效地用于后续的相似性计算和数据选择。

3.  **数据选择算法（Data Selection Algorithm）**:

-   对于验证集的每个子任务，计算其平均梯度特征。
-   使用定义好的公式（如论文中的 InfAdam）来评估训练数据点对验证数据点的影响。

-   影响力是怎么评估的？

-   **计算梯度特征**：对于每个验证数据点 𝑧′，计算其在模型参数 𝜃*θ* 下的梯度 ∇ℓ(𝑧′;𝜃)
-   **使用LoRA进行预热训练**：通过LoRA方法对模型进行预热训练，以获取模型在训练数据上的梯度 Γ(𝑧,𝜃)。
-   **计算Adam更新**：对于每个训练数据点 𝑧，使用Adam优化器的状态来计算其对应的更新 Γ(𝑧,𝜃)
-   **计算影响**：对于每个训练数据点 𝑧 和验证数据点 𝑧′，计算它们之间的影响
-   **选择数据点**：根据计算出的影响分数，选择对验证数据点影响最大的训练数据点，这些数据点被认为对模型在目标任务上的性能提升最有影响力。

-   选择对验证子任务影响最大的训练数据点，以构建训练集。

4.  **训练目标模型（Training Target Model）**:

-   使用选定的数据子集来训练目标模型。

### DEITA：WHAT MAKES GOOD DATA FOR ALIGNMENT? A COMPREHENSIVE STUDY OF AUTOMATIC DATA SELECTION IN INSTRUCTION TUNING

> [https://arxiv.org/pdf/2312.15685.pdf](https://arxiv.org/pdf/2312.15685.pdf)

先对数据进行复杂性和质量评分，再通过多样性进行数据筛选。

选择了两块候选数据集：

-   Sota：收集大模型的SOTA方法中的数据集，假设这些数据使用了相对复杂、多样和高质量的指令数据，涉及WizardLM（Alpaca）、WizardLM（ShareGPT） 、UltraChat和ShareGPT（Vicuna），共计300k数据。
-   Base：收集Alpaca、Dolly、OAssit和FLAN 2022数据作为基础指令数据集，共计100k数据。

  

1.  **复杂性（Complexity）**:

-   论文提出了一种名为 EVOL COMPLEXITY 的方法，通过增加约束、深化、具体化和增加推理步骤来逐渐提高单个数据点的复杂性。
-   使用一个小规模的种子数据集，对每个指令样本进行多次迭代，每次迭代都增加复杂性，生成不同复杂度的指令集合。
-   利用 ChatGPT 对这些不同复杂度的指令进行排名和评分，以获得复杂性分数。
-   基于这些分数，训练一个模型（如 LLaMA-1 7B）来预测给定指令的复杂性分数。

2.  **质量（Quality）**:

-   论文设计了 EVOL QUALITY 方法，通过提升响应的帮助性、相关性、深度、创造力和附加细节来提高响应的质量。
-   类似于 EVOL COMPLEXITY，对于给定的指令，通过迭代方式提升响应质量，生成不同质量的响应集合。
-   ChatGPT 被用来对这些响应进行排名和评分，以获得质量分数。
-   使用种子数据集的分数来微调 LLaMA-1 7B，使其能够基于提供的指令-响应对预测质量分数。

3.  **多样性（Diversity）**:

-   为了保持所选数据的多样性，论文提出了一种基于模型嵌入的迭代方法，选择能够为已选数据集贡献多样性的样本。
-   使用一个指标函数来确定新样本是否增加了多样性，只有当新样本与已选数据集的**嵌入距离（相似性）**超过某个阈值时，才将其添加到数据集中。

4.  **综合选择策略（Score-First, Diversity-Aware Data Selection）**:

-   论文提出了一种结合复杂性和质量分数的策略，通过将两者相乘得到一个综合分数（s = c \* q），并根据这个分数对数据进行排序。
-   采用一种分数优先、多样性感知的数据选择策略（πDEITA），首先根据综合分数对所有样本进行排序，然后迭代选择数据，同时使用 REPR FILTER 策略来维持数据的多样性。

5.  **训练 DEITA 模型**:

-   使用通过上述方法选择的数据集对预训练模型进行微调，得到 DEITA 模型系列。

论文的实验结果表明，DEITA 模型在使用自动选择的较少数据样本（6K SFT 数据样本）的情况下，性能优于或与现有的开源对齐模型相当。此外，当进一步使用直接偏好优化（DPO）进行训练时，DEITA 模型的性能得到了进一步提升。

总结来说，论文中的数据筛选方法是一个综合考虑复杂性、质量和多样性的自动化策略，通过精心设计的评分系统和迭代选择过程，以期用更少的数据实现更高效的模型对齐。

一般的，指令数据集中的一条数据包含（指令, 输入, 输出）这三部分，举个例子如下所示：

```plain
指令：写一篇关于以下主题的文章
输入：校园安全
输出：校园安全是学校必须高度重视的问题，涉及到师生的生命财产安全。建立安全意识，制定严格的规章制度，加强安全巡查和应急预案，是确保校园安全的关键。
```

不过很多时候对于上述三部分中的"指令"和"输入"划分的不是那么清晰，比如下面这条数据基本可以认为和上述例子是相同的：

```plain
输出：校园安全是学校必须高度重视的问题，涉及到师生的生命财产安全。建立安全意识，制定严格的规章制度，加强安全巡查和应急预案，是确保校园安全的关键。
```

所以指令数据集中的一条数据可能包含三部分（指令, 输入, 输出），也可能只有两部分（指令, 输出）。

该方法的整体流程大致有如下几个步骤：

1.  人工设计了**175个表示不同任务的指令（初始指令怎么选取）**，并且给每条数据都编写了（指令, 输入, 输出）/（指令, 输出），将这175条数据作为种子池。
2.  使用模型生成新的指令；
3.  对该模型生成的指令判断是否分类任务；
4.  使用模型生成实例；
5.  对上述模型生成的数据进行过滤和后处理；
6.  将经过过滤和后处理的数据添加到种子池中；
7.  一直重复上述2到6步直到种子池有足够多的数据；

接下来逐步分解

### 使用模型生成新的指令

先从种子池中随机抽取6个人工编写的指令，再随机抽取2个之前步骤中模型生成的指令，总共8个指令。以如下的模版格式组织之后，输入给模型，让模型输出一个新的指令。

![image.png](/img/yuque/计算机/大模型/2._模型微调及使用方式调研/assets/指令微调如何获取高质量数据-8.png)

### 判断指令是否属于分类任务

分类任务时，其输入里面偏向于只生成一个类别，所以需要单独识别出来。（为什么偏向一个类别？）

判断指令是否属于分类任务的操作如下：在种子池中随机挑选12条分类指令和19条非分类指令，然后加上新生成的指令，以下的模版格式组织之后，输入给模型，让模型输出新生成的指令是否分类任务。

![image.png](/img/yuque/计算机/大模型/2._模型微调及使用方式调研/assets/指令微调如何获取高质量数据-9.png)

### 生成实例

在给定指令之后，生成（输入, 输出）这个实例对时还有两种策略。一种是先生成输入，后生成输出，即输入优先策略；另一种是先生成输出，后生成输入，即输出优先策略。分类就是输出优先，先有类别，再生成输入。

#### 输入优先

具体生成实例的操作步骤为：在种子池中随机抽取 k 条数据，以如下的prompt模版的形式组合之后，输入给模型，让模型为最后的指令生成相应的实例。如下所示：

![image.png](/img/yuque/计算机/大模型/2._模型微调及使用方式调研/assets/指令微调如何获取高质量数据-10.png)

#### 输出优先

先标签，再 input

具体的步骤和输入优先基本相同：在种子池中随机抽取 k 条在之前的步骤中已经标记为分类的数据，以如下的prompt模版的形式组合之后，输入给模型，让模型为最后的指令生成相应的实例。

![image.png](/img/yuque/计算机/大模型/2._模型微调及使用方式调研/assets/指令微调如何获取高质量数据-11.png)

### 过滤以及后处理

-   为了数据的多样性，新生成的指令只有与种子池中的指令的 **ROUGE-L** 小于0.7时才会添加进入种子池；
-   排除一些无法被语言模型处理的指令，比如涉及图像、图片、图形的指令；
-   在给指令生成实例时，会过滤掉输入相同但是输出不同的实例；

### 生成的数据集质量分析

-   5.2w 指令和8w 条实例。
-   生成的指令有含义，能表示一个任务的占比为92%；
-   给每个指令生成合适的输入的占比为79%；
-   生成的输出是指令和输入的正确结果的占比为58%；
-   指令、输入、输出，这三个字段全对的占比为54%；

可以看出质量其实不太高。但在微调 GPT3 后，提升还是很大的。接近了 openai发布的模型 text-davinci-0013（instruct-GPT\_001)

## 自动生成 Wizard 系列工作

> -   WizardLM: https://arxiv.org/abs/2304.12244
> -   WizardCoder: https://arxiv.org/abs/2306.08568
> -   WizardMath: https://github.com/nlpxucan/WizardLM/tree/main/WizardMath

### WizardLM（**Evol-Instruct）**

在有监督微调（SFT）阶段，需要让人去写开放域的大量指令，以便让模型能够遵循用户特定的目标。然而，该过程面临着以下挑战：

-   整个标注过程十分昂贵和耗时
-   人工创建的指令的难度级别分布偏向于简单或中等，而困难的指令较少

本文展示了一种利用 LLM 代替人类创建具有不同复杂度的大量指令数据的方法。从一组初始指令开始，我们使用提出的 **Evol-Instruct 逐步将其重写为更复杂的指令**。然后，我们混合所有生成的指令数据，对 LLaMA 进行**微调**。我们将生成的模型称为 WizardLM。整体流程为：

1.  **Instruction Evolution**：从一个初始指令集出发，扩展出更丰富和复杂的指令集

1.  in-depth evolving：深度扩展，本文设计了 5 种类型的 prompt：添加约束，深化，具体化，增加推理步骤以及输出复杂化。
2.  in-breadth evolving：增加话题和技巧的覆盖度和多样性

2.  **Response Generation**：使用 LLM 为扩展的指令生成回答
3.  **Instruction Elimination**：作者提出了四种判断标准：

1.  没有提供了信息增益（使用 ChatGPT 判断）
2.  让 LLM 难以产生回复，例如回答中包含“sorry”
3.  回复中只包含标点和停词
4.  复制了 prompt 中的一些词，例如“given prompt”和“#Rewritten Prompt#”等

4.  **Finetuning**： 将初始指令和扩展指令数据混合打乱，以微调 LLM

一个示例：

说出中国的首都？ -> 众所周知，中国是一个地大物博的国家，balabala... ，那中国的首都是哪座城市呢？

不同于self-instruct的是其做了更精细的prompt engineering来进行生成。具体来说其从深度和广度两个方向对prompt进行了进化。

### WizardCoder

wizardcoder 是基于开源的”代码大模型“StarCoder的，做了”指令进化“的扩展：

-   通过**消除深化（removing deepening）**、**复杂化输入（complicating input）**和**广度进化（in-breadth evolving）**来简化”进化指令“。
-   通过**统一进化提示模板**，简化了进化提示的形式。
-   针对代码域的具体特点，我们增加了两条进化**指令（instructions）**：**代码调试**（code debugging）和**代码时空复杂度约束**（code time-space complexity constraints）。

举个例子：

```python
向原始问题添加新的约束和要求，增加大约 10 个额外的单词。
将编程任务中常用的需求替换为不太常见且更具体的需求。
如果原来的问题只需几个逻辑步骤就可以解决，请添加更多的推理步骤。
提供一段错误代码作为参考，增加误导。
提出更高的时间或空间复杂度要求，但请不要频繁这样做
```

使用starcoder 15b，作为基座模型、全量 SFT。

## 自动生成 Backtranslation

> -   Self-Alignment with Instruction Backtranslation
> -   https://arxiv.org/pdf/2308.06259.pdf

提出一种高效地创建高质量的指令数据的方法，即指令回传（instruction backtranslation），参考了机器翻译中回译（backtranslation）的方式。

简而言之就是数据中存在高质量的指令对应的回应数据，并且可以根据这部分数据预测对应的指令。

1.  根据无标签数据（高质量回复）生成对应的指令
2.  利用模型对数据质量打分，挑选高分也就是高质量的数据
3.  基于挑选出来的高质量数据优化打分模型
4.  利用优化的模型对数据质量重新打分
5.  后续不断重复“打分”、“筛选高质量数据”、“优化模型”的步骤，挑选出高质量的数据

这不会学歪了？初始高质量数据有多少条能保证不歪？论文里是 3.2k。

## Unnatural Instructions

Unnatural Instructions是一个包含大约24万个实例的指令数据集，使用InstructGPT构建。数据集中的每个实例都有四个组件: INSTRUCTION,INPUT, CONSTRAINTS,OUTPUT。“INSTRUCTION”是用自然语言对教学任务的描述。“INPUT”是自然语言中的参数，用于实例化指令任务。“CONSTRAINTS”是任务输出空间的限制。“OUTPUT”是在给定输入参数和约束条件下正确执行指令的文本序列。

作者首先从人工构建的Super-Natural Instructions dataset中对种子指令进行采样。然后，他们提示InstructGPT引出一个新的(instructions, inputs, constraints)对，其中有三个种子指令作为演示。接下来，作者通过随机改写指令或输入来扩展数据集。指令、输入和约束的连接被馈送到InstructGPT以获得输出。

## xP3

xP3(Crosslingual Public Pool of Prompts)是一个多语言指令数据集，由46种语言的16种不同的自然语言任务组成。数据集中的每个实例都有两个组件:“inputs”和“targets”。“inputs”是一种自然语言的任务描述。“targets”是正确遵循“inputs”指令的文本结果。

xP3中的原始数据来自三个来源:英语指令数据集P3, P3中的4个英语未见任务(例如，翻译，程序合成)和30个多语言NLP数据集。作者通过从PromptSource中采样人工编写的任务模板，然后填充模板，将不同的NLP任务转换为统一的形式化，构建了xP3数据集。

  

# 附带评价指标

[NLP评估指标之ROUGE](https://zhuanlan.zhihu.com/p/543103440)

ROUGE通过将模型生成的摘要或者回答与参考答案（一般是人工生成的）进行比较计算，得到对应的得分。ROUGE指标与BLEU指标非常类似，均可用来衡量生成结果和标准结果的匹配程度，不同的是ROUGE基于[召回率](https://www.zhihu.com/search?q=%E5%8F%AC%E5%9B%9E%E7%8E%87&search_source=Entity&hybrid_search_source=Entity&hybrid_search_extra=%7B%22sourceType%22%3A%22article%22%2C%22sourceId%22%3A%22543103440%22%7D)，BLEU更看重准确率。在论文中主要提到了4种方法，分别是Rouge−N、Rouge−L、Rouge−W、Rouge−S。

Rouge-N实际上是将模型生成的结果和标准结果按N-gram拆分后，计算召回率。分子表示所有样本的标准结果按N-gram拆分后与生产结果按N-gram拆分后匹配上个数的和；分母表示所有样本的标准结果，按N-gram拆分后的和。

Rouge-L的L表示: Longest Common Subsequence，Rouge-L的计算利用了最长公共子序列。最长公共子序列去算准召率和 F 值，F 值就是R-L

ROUGE-W 是 Rouge-L 里面，对 LCS 连续片段的权重进行增加。这也比较符合预期。
