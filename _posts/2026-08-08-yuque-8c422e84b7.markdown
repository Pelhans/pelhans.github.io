# 论文解读：Benchmarking AI Agent Memory: Is a Filesystem All You Need?（2025）

> 一句话总结：Letta（MemGPT 原团队）的基准报告发现，仅把对话历史存进文件、给 agent 一套 `grep`/`search_files`/`open` 工具，GPT-4o-mini 就在长程记忆基准 LoCoMo 上拿到 **74.0%**——高于专用记忆系统 Mem0 的 68.5%，说明"记忆质量更多取决于 agent 如何管理上下文，而非检索机制的复杂度"。

> 性质说明：你提到的这篇并非正式 arXiv 论文，而是 **Letta 公司于 2025 年 8 月发布的工程基准博客 / 技术报告**（标题即 *Benchmarking AI Agent Memory: Is a Filesystem All You Need?*）。它虽未走同行评审，但因作者正是 MemGPT/Letta 团队、且结论对 agent 记忆设计影响很大，被社区广泛当作该方向的代表性工作引用。下文数字均来自该博客原文。

## 1\. 背景与动机

MemGPT 之后，记忆系统百花齐放：Mem0、Zep/Graphiti、LangMem 等纷纷把"记忆"做成可插拔服务，背后用向量库或知识图谱。但 Letta 团队提出一个尖锐质疑：**这些专用记忆工具真的比"让 agent 自己管理文件"更好吗？** 他们的动机来自两点观察：(1) 记忆工具的效果高度依赖底层 agent 会不会用——再强的检索器，agent 调用不好也白搭；(2) 当前记忆评测（如 LoCoMo）主要测单跳检索，而非真实 agentic 记忆，基准本身可能"测错了东西"。

## 2\. 核心问题

1.  在长程对话记忆基准上，**一个只依赖文件系统的简单 agent，能否胜过复杂专用记忆系统**？

2.  记忆效果的瓶颈，究竟是"检索机制的复杂度"，还是"agent 管理上下文的能力"？

3.  当前记忆基准（LoCoMo 等）是否真的衡量了 agent 记忆，还是只衡量了检索？

## 3\. 方法与架构

做法极简：把 LoCoMo 的对话历史整段写入一个文件，作为"附件"连到 Letta agent，再赋予它文件操作工具：

```plain
   LoCoMo 对话历史 ──写入──▶ 一个文本文件(被嵌入,支持语义检索)
                                  │
                                  ▼
                           Letta Agent (GPT-4o-mini)
                           ┌──────────────────────────┐
                           │ 工具:                      │
                           │  · search_files 语义/向量检索│
                           │  · grep         文本匹配    │
                           │  · open/close   打开文件    │
                           │  · answer_question 作答     │
                           └────────────┬─────────────┘
                                        │ 工具规则:必须先 search_files
                                        │ 反复检索直到调用 answer_question
                                        ▼
                                   最终答案
```

关键设计：agent **部分自主**（tool rules 限定调用模式）——必须先 `search_files`，可多次迭代换关键词检索，直到自行决定调用 `answer_question` 终止。文件在 Letta 中被自动解析并嵌入，支持语义搜索；文本匹配用 `grep`。整个过程**没有任何专用记忆抽象**——没有知识图谱、没有抽取管线，只有"文件 + 基础文件工具"。

## 4\. 关键实验与结论

在 **LoCoMo**（长对话问答基准）上：

-   **Letta Filesystem + GPT-4o-mini = 74.0% 准确率**，且几乎未做 prompt 调优。

-   对照 **Mem0 最强图变体自报 68.5%**（Mem0 论文表内：graph 68.44%、vector 66.88%），即文件系统方案以更弱的模型（GPT-4o-mini vs 更强模型）反超。

-   参考 Mem0 论文中的 **Full-Context 基线（把整段对话塞进 prompt）= 72.90%**；也就是说文件系统方案不仅胜过专用记忆库，也逼近/超过"暴力全量上下文"的上限，且成本远低于全上下文（全上下文每查询约 26K token、p95 延迟 17s）。

-   结论：agents 对训练数据中常见的文件操作极其熟练，能自己**改写查询、迭代检索**，比"把原问题直接丢给单跳检索器"有效得多。

## 5\. 贡献与创新点

-   **对"记忆工具复杂度"的祛魅**：用最简架构证明，在现有基准上复杂记忆系统并不必然优于朴素文件检索，震动了记忆系统赛道。

-   **提出正确问题**：把焦点从"用什么数据库/图谱"转移到"agent 如何在负载下管理上下文"，为后续记忆评测（agentic memory 而非 retrieval）定调。

-   **工程可落地**：文件系统是 LLM 训练数据里的"母语"工具，零额外抽象、易审计、易持久化，直接可被 harness 复用。

## 6\. 局限与争议 / 后续工作

-   **局限**：LoCoMo 偏单/少跳检索，未充分代表需要复杂关系推理的真实长期记忆；74.0% 依赖 GPT-4o-mini 的检索能力，对更小的模型未必成立；未与最新图/分层方案（如 MemoryOS 的 49% 提升、ByteDance 的权重内记忆）做同条件对照。

-   **争议**：Mem0 曾发布"跑过 MemGPT"的 LoCoMo 数字，Letta 团队公开表示无法复现其 backfill 方式、且 Mem0 未回应澄清请求——基准可比性本身存疑。

-   **后续/相关**：

-   *Mem0*（arXiv:2504.19413, 2025）——结构化抽取+图记忆，仍是在成本/延迟上对标全上下文。

-   *MemoryOS*（arXiv:2506.06326, 2025）——仿 OS 段页式的四模块记忆，LoCoMo 上 F1 +49.11%。

-   *LongMemEval*（ICLR 2025）——更难的 agentic 长程记忆基准，正弥补 LoCoMo 的单跳偏向。

## 7\. 与 Agent Harness 的关系

对 harness 工程师的可操作建议：

1.  **优先把"文件 + 检索工具"作为记忆基线**。在引入 Mem0/Zep 等重架构前，先用文件系统挂对话/文档、给 agent `grep`/`search_files` 工具——往往已够用且更易调试；复杂记忆系统应作为"证明有必要"之后的升级。

2.  **让 agent 拥有"迭代检索"的自主权**。不要只把用户原问题丢给一次性检索；通过工具规则允许 agent 改写查询、多次检索、再作答（类似 Letta 的 tool rules），记忆效果更多来自这种上下文管理而非底层存储。

3.  **评测记忆要测 agent，而非只测检索器**。在 harness 内用 agentic 长程基准（LoCoMo/LongMemEval）端到端测，避免被"检索器单跳指标"误导而过度设计记忆子系统。
