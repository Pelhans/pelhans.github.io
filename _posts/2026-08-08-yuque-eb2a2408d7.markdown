# 基础知识

1.  经典 Transformer 的整体结构，能口述出来，代码能手撸出来

1.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-1.png)
2.  流程

1.  先对输入进行切词，现在流行的是 BPE 切词

1.  BPE 切词就是按照词频统计，每一轮把共现频率最高的结合再一起，加入词表，然后不断迭代，直到达到预设词表大小/不能再合为止
2.  除了 BPE 还有其他的切词，比如WordPice（用训练好的语言模型，预测两个subtoken 结合的概率，而不是统计，优点的考虑了语义，缺点是在新领域时就比较麻烦）

2.  对切词后结果进行映射，得到对应的 id
3.  用 id 去查表得到 token embedding
4.  再加上/ 乘上 position embedding

1.  几种常见 pos embedding

1.  可学习的 pos：初始化参数，让模型自己学
2.  sin embedding：$\left\{ \begin{aligned} PE_{2i}(p) = sin(\frac{pos}{10000^{\frac{2i}{d_{model}}}}) \\ PE_{2i+1}(p) = cos(\frac{pos}{10000^{\frac{2i}{d_{model}}}})  \end{aligned} \right.$

1.  这种构造的函数能够尝试学习相对位置信息，不同位置间的 token 是线性关系

3.  RoPE：给输入乘上一个旋转矩阵，使其旋转 (m-n) \* theta 角，用来表达两个输入向量位置 (m, n) 间的相对位置信息![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-2.png)
4.  AliBi：在 q\_m 和k\_n 相乘后，再加上他们之间的相对位置差(n-m）\* 坡度

5.  经过 mutli-head attention:

1.  有多个头，之前的维度是 d\_model，有 n\_heads，那每个头的维度就是 dk = d\_model/n\_heads
2.  输入乘以 $W_{i}^{Q} \in \mathbb{R}^{d_{model} \times d_{k}}$，$W_{i}^{K} \in \mathbb{R}^{d_{model} \times d_{k}}$, $W_{i}^{V} \in \mathbb{R}^{d_{model} \times d_{v}}$, $W_{i}^{O} \in \mathbb{R}^{d_{model} \times hd_{v}}$，得到 Q K V [n, dk]

6.  做 pre-norm 或 post norm

1.  $Pre Norm : x_{t+1} = x_{t} + F_{t}(Norm(x_{t}))$
2.  $Post Norm : x_{t+1} = Norm(x_{t} + F_{t}(x_{t}))$

7.  过 FFN：

1.  $FFN(x) = 激活函数(xW_{1} + b_{1})W_{2} + b_{2}$，激活函数比如 ReLU 或者 GeLU 等

8.  再过 pre-norm 或 post norm

3.  Transformer 里面的数据流动（维度变化）

1.  输入 embedding 后(token embeddign + pos emeddding 后) [n, d\_model], n 是输入长度
2.  一份走残差，维度不变，另一份走 MHA

1.  先是多头拆分 q= [n, d\_model], dk=d\_model/n\_heads
2.  每个头有权重矩阵 Wq, Wk, Wv $\in \mathbb{R}^{d_{model} \times d_{k}}$，分别和 q相乘得到 Q, K, V [n, d\_k]
3.  sfotmax 后的维度是 [n, dk] , MHA的输出时会把每个头维度进行拼接，得到 [n, d\_model]，并乘上一个 Wo 得到 [n, d\_model] 的向量

3.  做 pre-norm 或 post norm

1.  维度不会改变，只改变里面的数值，比如减去均值或除以方差

4.  FFN：先降维矩阵，经过激活函数后再经过升维度矩阵
5.  后面是 norm + add ，维度都不变

2.  **Self-Attention的表达式**$softmax(\frac{QK^{T}}{\sqrt{d_{k}}}) V$
3.  **为什么上面那个公式要对QK进行scaling**

1.  假设之前的q 和 k 的方差是1，相乘后每个维度的方差都是1，但有个 sun 过程，导致方差编程了 dk，最终方差变大
2.  scaling后进行softmax操作可以使得输入的数据的分布变得更好，你可以想象下softmax的公式，数值会进入敏感区间，防止梯度消失，让模型能够更容易训练。

4.  **self-attention一定要这样表达吗？**

1.  不一定，只要可以建模相关性就可以。当然，最好是能够高速计算（矩阵乘法），并且表达能力强（query可以主动去关注到其他的key并在value上进行强化，并且忽略不相关的其他部分），模型容量够（引入了project\_q/k/v，att\_out，多头）。

5.  **有其他方法不用除根号** $d_{k}$ **吗？**

1.  **加 norm**

6.  **为什么transformer用Layer Norm？有什么用？**

1.  任何norm的意义都是为了让使用norm的网络的输入的数据分布变得更好，也就是转换为标准正态分布，数值进入低敏感度区间
2.  以减轻 ICS问题，从而更容易训练。

7.  **为什么不用BN？**

1.  对不同样本同一特征的信息进行归一化没有意义：三个样本（为中华之崛起而读书；我爱中国；母爱最伟大）中，“为”、“我”、“母”归一到同一分布没有意义。

8.  **Bert为什么要搞一个position embedding？**

1.  因为仅仅有之前提到的self-attention无法表达位置信息（对位置信息不敏感），比如说“1+1=2”和“1+2=1”是一样的，因此需要增强模型针对位置的表达能力。

9.  **Bert为什么三个embedding可以相加？**

1.  **本质可以看作一个特征的融合，强大如 BERT 应该可以学到融合后特征的语义信息的。**

10.  **transformer为什么要用三个不一样的QKV？**

1.  为了增强网络的容量和表达能力。而且都一样的 Q 做 att 没啥意义

11.  **为什么要多头？举例说明多头相比单头注意力的优势**

1.  **拆分到多个子空间，提升表达能力。不同的kernel 的感觉**

12.  **为什么Bert中要用WordPiece/BPE这样的subword Token？**

1.  避免OOV（Out Of Vocabulary），也就是词汇表外的词。在NLP中，通常会预先构建一个词汇表，包含所有模型能够识别的词。然而，总会有一些词没有出现在预先构建的词汇表中，这些词就是 OOV。传统的处理方式往往是将这些 OOV 映射到一个特殊的符号，如 <UNK>，但这种方式无法充分利用 OOV 中的信息。例如，对于词汇表中没有的词 "unhappiness"，如果直接映射为 <UNK>，则模型就无法理解它的含义。
2.  用char级别的，每个字符要承担过多的语义，很难学习
3.  因此用BPE切词到适当粒度，可以在尽可能避免OOV的前提下，减少一次多义的可能

13.  **Bert中为什么要在开头加个[CLS]?**

1.  **汇集整个句子层面的信息**

14.  **不用[CLS]的语义输出，有其他方式可以代替吗？**

1.  对BERT的所有输出词向量（忽略[CLS]和[SEP]）应用MaxPooling和AvgPooling，再或者 FFN 也许可以

15.  **Bert中有哪些地方用到了mask?**

1.  预训练任务Masked Language Model (MLM)、self-attention的计算、下游任务的decoder

16.  **预训练阶段的mask有什么用？**

1.  把输入的其中一部分词汇随机掩盖，模型的目标是预测这些掩盖词汇。这种训练方式使得每个位置的BERT都能学习到其上下文的信息。

17.  **BERT中attention中的mask有什么用？**

1.  在attention中我们不希望一个token去注意到这些padding的部分，因为实际场景下它们是不存在的，所以attention中的mask就是来处理掉这些无效的信息的。具体实现是在softmax前每个都设为-inf（或者实际的场景一个很小的数就可以），然后过完softmax后"padding"部分的权重就会接近于零，query token就不会分配注意力权重了。

18.  **decoder中的mask有什么用？**

1.  模拟inference的过程，让模型看不到未来的tokens的信息。

19.  **Bert中self attention 计算复杂度如何？**

1.  **o(d^2)**

20.  **有什么技术降低复杂度提升输入长度的？**

1.  比如Sparse Attention，放弃对全文的关注，只关心局部的语义组合，相当于self-attention上又加了一些mask，这样的话就可以降低复杂度，而且下游任务的语义关联性的体现往往是局部/稀疏的。

21.  **为什么以前char level/subword level的NLP模型表现一般都比较差，但是到了bert这里就比较好？**

1.  **以前的模型容量有限，不足以学好 char/subword 级别的上下文相关语义信息。**

22.  **Bert为什么要使用warmup的学习率trick？**

1.  由于刚开始训练时，模型的权重(weights)是随机初始化的，此时若选择一个较大的学习率,可能带来模型的不稳定(振荡)，选择Warmup预热学习率的方式，可以使得开始训练的几个epoches或者一些steps内学习率较小，在预热的小学习率下，模型可以慢慢趋于稳定,等模型相对稳定后再选择预先设置的学习率进行训练，使得模型收敛速度变得更快，模型效果更佳。
2.  warmup就是把lr从一个较小的值线性增大到预设，以减缓参数震荡，让训练变得比较smooth，当模型参数量上来后这种策略变得更重要了。

23.  **为什么说GPT是单向的Bert是双向的？**

1.  这也是decoder-only和encoder-only的区别。

1.  decoder-only架构的生成模型在输出的时候只能看到当前位置前的tokens，也就是屏蔽了序列后面的位置，以适配NTP任务。
2.  encoder-only架构的编码模型在输出的时候可以利用前后位置的tokens，以适配MLM任务。
3.  具体的做法是self-attention加不加casual mask，也就是遮不遮住序列后面的内容。

24.  **Bert如何处理一词多义？**

1.  self-attention解决的，搭配上MLM的任务，就可以让每个token会注意到上下文的其他token来得到自己的embedding。

25.  **Bert中的transformer和原生的transformer有什么区别？**

1.  最重点的区别在于位置编码：原生的transformer是最经典的Sinusoidal绝对位置编码。而BERT中变成了可以学习的参数，也就是可学习位置编码。

26.  **attention计算方式以及参数量，attention layer手写，必考。**

1.  **简易代码**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super(MultiHeadAttention, self).__init__()
        self.num_heads = num_heads
        self.d_model = d_model
        assert d_model % self.num_heads == 0

        # Define the dimension of each head or subspace
        self.d_k = d_model // self.num_heads

        # These are still of dimension d_model. They will be split into number of heads 
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)

        # Outputs of all sub-layers need to be of dimension d_model
        self.W_o = nn.Linear(d_model, d_model)
    
    def scaled_dot_product_attention(self, Q, K, V, mask=None):
        batch_size = Q.size(0)
        K_length = K.size(-2)
    
        # Scaling by d_k so that the soft(arg)max doesn't explode
        QK = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
    
        # Apply the mask
        if mask is not None:
            QK = QK.masked_fill(mask.to(QK.dtype) == 0, float('-inf'))
    
        # Calculate the attention weights (softmax over the last dimension)
        weights = F.softmax(QK, dim=-1)
    
        # Apply the self attention to the values
        attention = torch.matmul(weights, V)
    
        return attention, weights

    def split_heads(self, x, batch_size):
        """
        The original tensor with dimension batch_size * seq_length * d_model is split into num_heads 
        so we now have batch_size * num_heads * seq_length * d_k
        """
        return x.view(batch_size, -1, self.num_heads, self.d_k).transpose(1, 2)

    def forward(self, q, k, v, mask=None):
        batch_size = q.size(0)

        # linear layers
        q = self.W_q(q)
        k = self.W_k(k)
        v = self.W_v(v)

        # split into multiple heads
        q = self.split_heads(q, batch_size)  
        k = self.split_heads(k, batch_size)  
        v = self.split_heads(v, batch_size)  

        # self attention
        scores, weights = self.scaled_dot_product_attention(q, k, v, mask)

        # concatenate heads
        concat = scores.transpose(1,2).contiguous().view(batch_size, -1, self.d_model)

        # final linear layer
        output = self.W_o(concat)

        return output, weights
```

27.  描述下 encoder only，decoder only，encoder-decoder。他们的区别是啥？

1.  encoder only 对应经典的 BERT，分类等任务好一些
2.  decoder only 对应 GPT，长文本生成能力强
3.  encoder-decoder 是 T5，条件生成好一些
4.  decoder only 会mask掉自己后面的token，encoder only 前后都能看到

28.  prefix attention和causal attention的区别是什么？

1.  prefix 部分的 attention 可以互相看到，其余部分的 attention 只能看到自己之前的
2.  causal attention 全部只能看到自己之前的文本

29.  prefix LM 和 causal LM 区别是什么？

1.  prefix LM（前缀语言模型）：在输入序列的开头添加一个可学习的任务相关的前缀，然后使用这个前缀和输入序列一起生成输出。这种方法可以引导模型生成适应特定任务的输出。
2.  causal LM（因果语言模型）：也称为自回归语言模型，它根据之前生成的 token 预测下一个 token。在生成文本时，模型只能根据已经生成的部分生成后续部分，不能访问未来的信息。

30.  涌现能力是什么？啥原因？

1.  是什么？

1.  涌现能力（Emergent Ability）是指模型在训练过程中突然表现出的新的、之前未曾预料到的能力。这种现象通常发生在大型模型中，原因是大型模型具有更高的表示能力和更多的参数，可以更好地捕捉数据中的模式和关联。随着模型规模的增加，它们能够自动学习到更复杂、更抽象的概念和规律，从而展现出涌现能力。

2.  原因 [大语言模型的涌现能力：现象与解释](https://zhuanlan.zhihu.com/p/621438653)

1.  数据量的增加：从大量的数据里学习到了应对各种上下文信息的能力
2.  模型参数量导致的质变：具有更高的表示能力和更多的参数，可以更好地捕捉数据中的模式和关联。随着模型规模的增加，它们能够自动学习到更复杂、更抽象的概念和规律，从而展现出涌现能力。
3.  评价指标的不平滑：评价指标比较严格时（如NER的 span 必须两侧完全正确才算对），但实际上随着优化，它的 span 在逐渐接近正确，但在指标上不会体现。

31.  什么是LLMs复读机问题？

1.  模型倾向于无限地复制输入的文本或者以过度频繁的方式重复相同的句子或短语。这种现象使得模型的输出缺乏多样性和创造性

32.  造成复读机问题的原因是什么？

1.  数据问题：训练数据中存在大量的重复文本或者特定句子出现频率较高
2.  训练目标的限制：自回归任务本身就是选取下一个概率最高的单词，所以可能本身就有这种倾向。解决方案是 topk 或者 top-p

33.  怎么解决复读机问题？

1.  上面说的，在解码阶段做功，比如加入温度、采用 top-k或者 top-p 解码策略。多样化训练数据，或者直接后处理策略禁止出重复的

34.  llama输入句子长度理论上可以无限长吗？

1.  答案是不能。首先从计算资源上，attention 的复杂度是长度的平方，内存不支持。其次过长的句子需要更强大的模型去处理上下文依赖，否则效果也不会好。而且在推理与训练的长度差距过大时，模型的效果也会下降的比较严重。

35.  那怎么解决或者说缓解呢？

1.  1\. RAG 的方式处理输入，先切分，再通过向量/文本检索召回相关片段 ，选取一部分让大模型处理。
2.  层次建模，先用大模型对能处理的小部分进行处理生成简短文本，再对聚合的简短文本进行处理。
3.  使用外推方案，能缓解输入过长的问题

36.  模型推理时的显存为什么占用那么大？

1.  模型参数占用显存：大语言模型通常具有巨大的参数量，这些参数需要存储在显存中以供推理使用。因此，在推理过程中，模型参数会占用相当大的显存空间。
2.  输入数据占用显存：进行推理时，需要将输入数据加载到显存中。对于大语言模型而言，输入数据通常也会占用较大的显存空间，尤其是对于较长的文本输入。
3.  中间计算结果占用显存：在推理过程中，模型会进行一系列的计算操作，生成中间结果。这些中间结果也需要存储在显存中，以便后续计算使用。对于大语言模型而言，中间计算结果可能会占用较多的显存空间。
4.  内存管理策略：某些深度学习框架在推理时采用了一种延迟释放显存的策略，即显存不会立即释放，而是保留一段时间以备后续使用。这种策略可以减少显存的分配和释放频率，提高推理效率，但也会导致显存一直占用的现象。

37.  大模型生成时的参数怎么设置？

1.  推理算法：选择合适的推理算法，top-p、top-k、beam search 等
2.  温度参数：在生成文本时，可以通过调整温度参数来控制生成的文本的多样性。较高的温度会增加生成文本的随机性和多样性，而较低的温度会使生成文本更加确定和一致。
3.  生成文本的最大长度或最小长度

38.  预训练数据Token重复是否影响模型性能?

1.  看占比，占比很低无影响
2.  占比高可能导致生成出现重复

39.  activation checkpointing 是什么？

1.  详见 [PyTorch 节省显存技巧：Activation Checkpointing](https://zhuanlan.zhihu.com/p/675561607)， 是一种用于减小内存占用的技术，即只是在需要时重新计算反向传播所需的**中间张量**，来避免保存这些中间张量。
2.  一旦构建了计算图，对 tensor.backward() 的调用将递归地计算梯度，直到存储了 .grad 的叶子节点。当这个过程停止时，计算图的角色结束并被丢弃（除非指定了 retain\_graph=True）。![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-3.png)

1.  什么是 Normalization？

1.  对其做平移和伸缩变换,将x的分布规范化成指定分布，如标准化方差和均值
2.  第一步可以对原分布进行调整, 转化为标准正态分布，第二步用学习到的参数 g（方差）和b（均值）得到新的分布
3.  新分布的参数模型训练和统计得到, 去除了与前面的层层耦合, 使得 参数的学习更加稳定有效.简化了神经网络的训练

2.  为什么要做 Normalization？

1.  梯度弥散、ICS、损失函数曲面变得平滑、对系统参数搜索空间进行约束（好的映射曲线应该是让数据曲线的分布尽量均匀尽量平滑)
2.  减少层与层间的耦合，减轻 ICS 问题
3.  损失函数曲面变得平滑

3.  常见的 Normalization 方法有哪些？

1.  layer norm、batch norm、rms norm 等

4.  介绍下 Layer Norm 是怎么做的？

1.  以 CNN 举例, 输入的维度是 (N, C, H, W)，则 LN 是在 C、H、W 三个维度上计算均值方差，即在每个样本内部做 normalization。  相当于在输入的 N 个数据上做 normalization,  最终得到 N 个均值方差。

1.  chatglm1

6.  介绍下 RMS Norm 是怎么做的？

1.  RMSNorm舍弃了中心化操作，归一化过程只实现缩放，缩放系数是均方根(RMS)，L-N的均值 为0时便是RMSNorm，RMS所做的只是缩放，不会改变数据原本的分布，有利于激活函数输出的稳定（缩放不改变向量方向）：

7.  哪些模型用了 RMS Norm？

1.  llama 系列、mistral、chatglm2 和 3、Qwen、baichuan 等

8.  顺道介绍下 batch Norm?

1.  以 CNN 举例, 输入的维度是 (N, C, H, W)，则 BN 是对 N、H、W 这三个维度进行 element-wise 的平均和方差计算，最终得到 C 个 均值和方差对。

9.  BN 应该放在激活函数前还是激活函数后？

1.  BN 的原始论文里是放在 Sigmoid/tanh 函数前的，理由是 BN 可以重整输入，减缓 sigmoid 饱和等问题。但也有很多评测论文指出，BN 放在激活函数后好一点（特指像 RELU 这种），理由是 ReLU 这类函数对输入的分布破坏比较严重，放在前面不能阻止这种现象。

10.  为什么 NLP 里用 LN 很少用 BN？

1.  输入文本间做统计没有意义。比如 我爱吃苹果。 和 今天是个好天气。 我和 今没啥联系。俩长度也不一样。

11.  pre Norm 和 post Norm 的区别？哪个更好？

1.  [为什么Pre Norm的效果不如Post Norm？](https://zhuanlan.zhihu.com/p/494661681)
2.  $Pre Norm : x_{t+1} = x_{t} + F_{t}(Norm(x_{t}))$
3.  $Post Norm : x_{t+1} = Norm(x_{t} + F_{t}(x_{t}))$
4.  结论：同一设置之下，Pre Norm结构往往更容易训练，但最终效果通常不如Post Norm
5.  为什么？

1.  梯度角度：pre-Norm的残差连接效应强，使得梯度的回传更容易，而Post-Norm的应用会使得梯度快速衰减，导致模型难以学习。
2.  模型深度角度：残差链接会导致模型实际深度小于模型的层数，这个本来也是残差连接的特点。根据上面的分析，Pre-Norm是典型的全局残差连接，而Post-Norm因为Layer-Norm的引入改变了这种残差连接，使得在相同层数的情况下，Post-Norm的实际深度比Pre-Norm更深，所以效果更好。

2.  两个输入向量位置 (m, n) 间的相对位置信息 用复数空间旋转 (m-n) \* theta 角来表示。

5.  具体怎么实现的？

1.  LLAMA 里的实现

```python
def precompute_freqs_cis(dim: int, seq_len: int, theta: float = 10000.0):
    # 计算词向量元素两两分组之后，每组元素对应的旋转角度
    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
    # 生成 token 序列索引 t = [0, 1,..., seq_len-1]
    t = torch.arange(seq_len, device=freqs.device)
    # freqs.shape = [seq_len, dim // 2] 
    freqs = torch.outer(t, freqs).float()
    # 计算结果是个复数向量，输入分别是模和角度，这里模设置为1
    # 假设 freqs = [x, y]
    # 则 freqs_cis = [cos(x) + sin(x)i, cos(y) + sin(y)i]
    # 可以看出每一个元素就是 e^{im\theta}
    freqs_cis = torch.polar(torch.ones_like(freqs), freqs)
    return freqs_cis

def apply_rotary_emb(
    xq: torch.Tensor,
    xk: torch.Tensor,
    freqs_cis: torch.Tensor,
) -> Tuple[torch.Tensor, torch.Tensor]:
    # 两两分组，每组内部表示为复数的实部和虚部
    # xq.shape = [batch_size, seq_len, dim]
    # xq_.shape = [batch_size, seq_len, dim // 2, 2]
    xq_ = xq.float().reshape(*xq.shape[:-1], -1, 2)
    xk_ = xk.float().reshape(*xk.shape[:-1], -1, 2)

    # 转为复数域，变成 [batch_size, seq_len, dim//2]
    xq_ = torch.view_as_complex(xq_)
    xk_ = torch.view_as_complex(xk_)

    # 应用旋转操作，然后将结果转回实数域
    # 元素对应相乘
    # xq_out.shape = [batch_size, seq_len, dim]
    xq_out = torch.view_as_real(xq_ * freqs_cis).flatten(2)
    xk_out = torch.view_as_real(xk_ * freqs_cis).flatten(2)
    return xq_out.type_as(xq), xk_out.type_as(xk)
```

2.  具备良好的外推性
3.  任何位置之间的相对距离在不同长度的句子中应该是一致的

11.  RoPE 的问题：

1.  虽然RoPE理论上可以编码任意长度的绝对位置信息，并且sin/cos计算就能将任意长度的相对位置信息表达出来，但是实验发现RoPE仍然存在**外推问题**，即测试长度超过训练长度之后，模型的效果会有显著的崩坏，具体表现为**困惑度（Perplexity，PPL）**等指标显著上升

12.  RoPE 的改进有哪些？

1.  位置线性内插：**将位置索引本身进行下采样或缩放**。具体来说，他们将原本在[0, 4096]范围内索引缩放到[0, 2048]（预训练的范围）的范围内。
2.  NTK-Aware Scaled RoPE（非线性内插）：

1.  非线性内插是改变RoPE的base而不是比例，从而改变每个RoPE维度向量与下一个向量的“旋转”速度。$RoPE = 10000^{-2i/d}  \rightarrow (10000·\alpha)^{-2i/d}$

13.  什么是长度外推问题

1.  试长度超过训练长度之后，模型的效果会有显著的崩坏，具体表现为**困惑度（Perplexity，PPL）**等指标显著上升

14.  长度外推问题的解决方法有哪些

1.  用更长的文本进行微调
2.  用 AliBI 位置编码
3.  RopE的线性内插和非线性内插

15.  ALiBi的思路是什么

3.  将单词拆分为字符序列并在末尾添加后缀“ </ w>”，统计单词频率。 本阶段的subword的粒度是字符。 例如，“ low”的频率为5，那么我们将其改写为“ l o w </ w>”：5
4.  统计每一个连续字节对的出现频率，选择最高频者合并成新的subword
5.  重复第4步直到达到第2步设定的subword词表大小或下一个最高频的字节对出现频率为1

2.  WordPice 如何构建词典

1.  WordPiece算法可以看作是BPE的变种。不同点在于，WordPiece基于概率生成新的subword而不是下一最高频字节对

1.  准备足够大的训练语料
2.  确定期望的subword词表大小
3.  将单词拆分成字符序列
4.  基于第3步数据训练语言模型
5.  从所有可能的subword单元中选择加入语言模型后能最大程度地增加训练数据概率的单元作为新的单元
6.  重复第5步直到达到第2步设定的subword词表大小或概率增量低于某一阈值

3.  BPE 和 wordpice 对比，优缺点

1.  BPE 优点：

1.  未登录词处理：BPE可以根据语料库中的频率和统计信息自适应地切分单词，能够处理未登录词和稀有词汇，提高模型的泛化能力。
2.  可扩展性：BPE可以通过迭代地合并频率最高的子词单元来逐步扩展词汇表，从而适应不同任务和领域的需求。

2.  BPE 缺点：

1.  BPE的切分粒度较细，生成的子词单元可能过多，导致词汇表膨胀，增加了模型的复杂度和计算资源的需求。
2.  BPE仅根据频率和统计信息进行切分，没有考虑到词汇的语义信息，可能导致一些切分结果不符合语言的语义结构。

# 指令微调

## 指令微调基础

1.  什么是指令微调？

1.  指令微调是指通过构建指令格式的实例，然后以有监督的方式对大语言模型进行微调。指令格式通常包含任务描述，一对输入输出以及示例（可选）。

2.  微调/训练时，OOM了怎么办？

1.  减少 batch\_size
2.  内存优化技术：如混合精度训练、梯度累计、激活检查点等技术
3.  合理设置样本长度，减小内存占用
4.  使用更小的模型。。。

3.  为什么要进行指令微调？

1.  通用模型虽然在 zero-shot 任务上有着不错的表现，但若想进一步提升需要结合领域数据进行针对性训练

1.  控制模型行为：大模型通常具有很高的复杂性和参数数量，其行为可能难以解释和控制。通过指令微调，可以引入特定的指令或约束，以约束模型的行为，使其更符合特定任务的需求。
2.  个性化适应目标任务：通过指令微调，可以在大模型的基础上，使用特定任务或领域的数据进行微调，使模型更好地适应目标任务的特点。
3.  针对性注入领域知识：有了大模型通用知识做基础，领域知识微调时学习的更快

4.  预训练和微调哪个阶段注入知识？

1.  通常认为，预训练阶段注入知识，微调阶段学习任务模式，提升在目标任务上的性能。

5.  微调的 loss 是什么？

1.  也是预测下一个词

6.  为什么SFT之后感觉LLM傻了？

1.  预训练特征的扭曲：微调数据和预训练数据差异比较大时，模型为了适应微调数据分布，会扭曲通用数据分布，导致通用能力变差。
2.  模型的过拟合：微调数据上对特定的任务过拟合了
3.  微调数据缺乏多样性：未能涵盖模型在新任务上可能遇到的各种输入情况。这可能导致模型在面对新的、与微调数据集不同的输入时出现困惑或错误的预测。
4.  微调数据质量差：微调数据集的标注可能存在错误或不准确的标签。这些错误的标签可能会对模型的性能产生负面影响，导致模型产生“傻”的行为。

7.  怎么缓解通用能力的丧失？

1.  控制微调数据的数量(不要太大)和学习率(太大的学习率忘得快)
2.  增加微调数据的多样性
3.  提升微调数据质量，质量大于数量
4.  混入通用任务数据，比如链家的论文里是 1：5 补充，一般在 1：5 到1：10 之间

8.  进行SFT操作的时候，基座模型选用Chat还是Base?

1.  **如果你既追求领域任务的效果，并且希望通用能力不下降，建议选择base模型作为基座模型**。
2.  如果你的领域任务与通用任务有很大的相关性，那这种二阶段SFT会提升你的领域任务的效果。
3.  **基于chat模型进行领域SFT，会很容导致灾难性遗忘，在进行领域任务SFT之后，模型通用能力会降低，如只追求领域任务的效果，则不用考虑**。

9.  有了 SFT，为什么还要 RLHF？

1.  RLHF 在安全和事实性上，会有很大提升
2.  可以在一定程度上提升模型的泛化性（SFT 的每个 token 是唯一正确的，RL 不是，可能只是众多可行路径中的一个）

10.  为什么 SFT 第二个 epoch loss 会突然下降？（适应数据、适应参数、适应梯度）

1.  初始数据分布差异较大，在第一个 epoch 学的基础分布，第二个 epoch 学到更加高级特征，指标发生了质变
2.  各种 norm 技术的参数，如果数据分布差异大的话要重新适配，第一个 epoch 在适应
3.  adam 等算法的动量梯度前期方向不稳定，后期数据积累多了更稳定

11.  领域模型词表扩增是不是有必要的？

1.  领域模型的词表扩增可以有助于提升模型在特定领域任务上的性能但会增加模型的计算和存储成本
2.  领域特定词汇：**如果目标领域中存在一些特定的词汇或术语，而这些词汇在通用的预训练模型的词表中没有覆盖到，那么词表扩增就是必要的**。通过将这些领域特定的词汇添加到模型的词表中，可以使模型更好地理解和处理这些特定的词汇。
3.  数据稀缺性：如果目标领域的训练数据相对较少，而通用预训练模型的词表较大，那么词表扩增可以帮助模型更好地利用预训练模型的知识，并提升在目标领域任务上的性能。

8.  **对话session级别的训练和拆开训练从原理上有什么区别？**

1.  **对话session级别的训练与拆开训练在原理上的主要区别在于对上下文信息的处理和训练数据的利用方式。下面具体对比这两种方法：**

1.  **对话session级别的训练：**

1.  **这种方法将整个对话会话作为单个样本进行训练，其中包含了所有的问题和答案序列。**
2.  **模型在训练时会接收整个会话的上下文信息，这有助于模型学习对话的流程和逻辑，并能更好地理解上下文中的各种信息。**
3.  **在计算损失时，只关注模型生成的答案部分和相应的结束标记 <eos>，这样可以提高效率，因为模型不需要在每个回答时都重新处理整个对话历史。**
4.  **这种方式可以减少重复数据的输入，提高数据利用效率，并且可以训练模型生成更加连贯和一致的回答。**

2.  **拆开训练：**

1.  **拆开训练方法将每一轮的对话拆分为单独的样本，每个样本只包含一次问题和答案。**
2.  **模型在每个样本上进行训练时，通常只能看到当前问题和之前的对话历史，而不是整个会话的上下文。**
3.  **这可能导致模型在预测答案时缺乏足够的上下文信息，尤其是在对话较长或者需要理解整个会话流程时。**
4.  **此外，由于数据的高度重复（每个样本都包含之前对话的重复内容），这可能会导致训练效率低下，并且增加了过拟合的风险。**

3.  **总的来说，session级别的训练更加注重整个对话上下文的连贯性和一致性，而拆开训练则可能导致模型对于每一轮对话的理解较为孤立，缺乏对整个会话流程的把握。session级别的训练通常在处理长对话和复杂对话场景时更为有效，而拆开训练可能在简单或短对话的场景下更为快速和方便。不过，选择哪种方法也取决于具体的应用场景和模型的能力。**

1.  RL过程中涉及到几个模型？

1.  4个，策略、critic、RM、ref 模型

1.  策略模型就是 LLM 模型，用第一步的 actor loss 进行优化（ae 乘上新旧模型的预测概率之商 prob/prob' 基本得到 actor loss 了）
2.  critic 模型：用来预测 V 的
3.  RM：奖励模型，给模型的最终输出打一个标量分，可能在训练过程中进行几次更新
4.  ref 模型：初始模型，用来防止对齐跑偏和采样的

2.  介绍下 PPO 算法的训练流程（在 LLM 中）[RLHF 技术详解](https://huggingface.co/blog/zh/rlhf)

1.  首先使用经过监督微调的大语言模型作为初始化策略模型$\pi_{\theta}$和$\pi_{old}$（两个SFT 后的 LLM 模型）
2.  将策略模型 $\pi_{old}$与环境进行交互，生成决策轨迹（生成一系列的 token）
3.  估计优势函数，来衡量实际奖励与期望奖励之间的差异

1.  Q 可以使用奖励模型计算获得
2.  V 通过评价模型获得，评价模型可以使用奖励模型来进行初始化，随着 PPO 的训练逐步优化

4.  计算 loss $L^{KLPEN}(\theta) = \hat{E}_{t}[\frac{\pi_{\theta}(a_{t}|s_{t})  }{\pi_{old}(a_{t}|s_{t})}\hat{A}_{t} - \beta KL[\pi_{old}(·|s_{t})， \pi_{\theta}（·|s_{t})    ]   ]$，用梯度上升更新策略模型的参数

3.  什么是优势函数？

1.  衡量当前输出与标准答案得分间的差距准确衡量当前输出与标准答案得分间的差距

4.  介绍下 Actor-Critic

1.  Actor-Critic是一种强化学习算法，结合了策略模型（演员）和值函数模型（评论家）。演员根据当前状态选择动作，评论家评估演员的策略并提供值函数估计。通过演员的策略梯度和评论家的值函数更新，算法可以同时进行策略改进和策略评估，从而提高学习效率和稳定性。Actor 就是我们的LLM， Critic 用来预测每步的价值 V

5.  写出策略梯度的优化目标公式

1.  $loss = -\frac{1}{N} \sum_{n=1}^{N} \sum_{t=1}^{T_{n}} (Q^{\pi}(s_{t}, a_{t}) - V^{\pi}(s_{t}))  \log(p_{\theta}(a_{t}^{n}|s_{t}^{n} ))$
2.  公式来源是：

1.  首先我们希望模型在整个时间步 t 内的期望奖励最大化，所以有公式$loss = -\frac{1}{N} \sum_{n=1}^{N} \sum_{t=1}^{T_{n}} R(t^{n}) \log(p_{\theta}(a_{t}^{n}|s_{t}^{n} ))$

1.  其中 其中 $R(t^{n})$是整个句子累积的奖励。$\log(p_{\theta}(a_{t}^{n}|s_{t}^{n} ))$ 是模型输出的某个 token 的 log\_prob

2.  但新问题是上面的奖励还是不够准确，如果能**准确衡量当前输出与标准答案得分间的差距**（**Advantage函数**）就好了。因此设计一个新的 loss $loss = -\frac{1}{N} \sum_{n=1}^{N} \sum_{t=1}^{T_{n}} (Q^{\pi}(s_{t}, a_{t}) - V^{\pi}(s_{t}))  \log(p_{\theta}(a_{t}^{n}|s_{t}^{n} ))$

1.  Q 是**动作**执行后的**累计奖励期望**：LLM 中，生成等于当前token后，后续所有路径的 Gt 的平均值。(Gt 是从当前时间步到结束状态的奖励之和)，在 A2C 里 $Q^{\pi}(s_{t}^{n}, a_{t}^{n}) = E[r_{t}^{n} + V^{\pi}(s_{t+1}^{n})] \sim r_{t}^{n} + V^{\pi}(s_{t+1}^{n})$
2.  V 是当前**状态**的**累计奖励期望**，相当于是当前所有可能输出的token的Q值的平均值，在 A2C 里用 critic 来预测 V
3.  所以优势函数可以写作 $Q^{\pi}(s_{t}^{n}, a_{t}^{n}) - V^{\pi}(s_{t}^{n}) \sim r_{t}^{n} + V^{\pi}(s_{t+1}^{n}) - V^{\pi}(s_{t}^{n})$

6.  写出 PPO 算法的 loss

1.  PPO算法的核心在于更新策略梯度，主流方法有两种，分别是KL散度做penalty，另一种是Clip剪裁，它们的主要作用都是限制策略梯度更新的幅度
2.  KL 散度：$L^{KLPEN}(\theta) = \hat{E}_{t}[\frac{\pi_{\theta}(a_{t}|s_{t})  }{\pi_{old}(a_{t}|s_{t})}\hat{A}_{t} - \beta KL[\pi_{old}(·|s_{t})， \pi_{\theta}（·|s_{t})    ]   ]$

1.  优势函数 A 前面乘的事重要性采样的东西

3.  Clip：$L^{CLIP}(\theta) = \hat{E}_{t}[\min(r_{t}(\theta)\hat{A}_{t}, clip(r_{t}(\theta), 1-\epsilon, 1+\epsilon  )\hat{A}_{t} )]$

1.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-22.png)

7.  介绍下 GAE 估计？

1.  一面是从结束位置到开始生成的位置，每一个 token 将奖励乘上一个折扣传递给前一个 token，另一面是 critic model 在每个 token 的位置上有一个预测的 value 值。如此2项分别是折扣的真实奖励值和预测 value 值，对这两项使用 td-error 等小技巧，就得到了每个 token 位置的 td-target，td-target 结合上预测 value 值再加以累计折扣就得到了 gae。

8.  PPO 中使用 GAE 的好处以及参数$\lambda$的作用是什么？

1.  Q 值估计不准，前期 V 不稳定，导致 Q 的偏差比较大。用GAE 可以更好的估计优势函数。GAE 是原始优势函数和纯累计折扣奖励估计得折中。Trlx 默认$\lambda$是 0.95
2.  比如从最后一个时间步 t+1 往 t 推导，优势函数可以写作$adv（s_{t}) = R(s_{t}) + \gamma V(s_{t+1}) - V(s_{t}) + \gamma \lambda \times (R(s_{t+1}) - V(s_{t+1}))$

1.  当 $\lambda$等于1时，就是用折扣累计奖励$G_{t}$去近似Q。$adv（s_{t}) = R(s_{t}) + \gamma R(s_{t+1}) - V(s_{t})$
2.  当$\lambda$等于 0 时，就是 actor-critic 的原始优势函数。$adv（s_{t}) = R(s_{t}) + \gamma V(s_{t+1}) - V(s_{t})$

9.  目标公式中衰减因子的作用，取大取小有什么影响？

1.  用于调整未来奖励的当前价值。0-1 之间的数，0表示完全不考虑未来的奖励，而1表示未来的奖励与当前奖励同等重要。

10.  奖励模型是怎么训练的？

1.  RM 的训练是 RLHF 区别于旧范式的开端。这一模型接收一系列文本并返回一个标量奖励，数值上对应人的偏好。比如构造 prompt 数据集，然后大模型生成，人工对大模型生成结果排名，将排名转化为标量分数，来训练奖励模型。
2.  模型选择：RM 可以是另一个经过微调的 LM，也可以是根据偏好数据从头开始训练的 LM。比如 OpenAI 用了 175B 的LM 和 6B 的RM、DeepMind 使用了 70B 的 Chinchilla 模型分别作为 LM 和 RM，一种直觉是，偏好模型和生成模型需要具有类似的能力来理解提供给它们的文本。）
3.  训练文本：人工标注、对话数据采样。比如构造 prompt 数据集，然后大模型生成，人工对大模型生成结果排名
4.  获取训练奖励数值：对 LM 生成的回答进行排名，比如用 ELO 系统建立一个完整的排名。再将排名结果归一化为训练用的标量奖励值

1.  如何将排名转化为分数？$分数 = \frac{R - R_{min}}{R_{max} - R_{min}} \times 分数范围$，其中 R 是ELO 排名，Rmin 和 Rmax 是所有参与者中最低和最高的排名，分数范围是希望将排名映射到的范围。

25.  介绍下 DPO 算法？DPO 的公式推导

1.  我这有一个其他路径的推导。。。

1.  首先我们有正常 PPO 的 loss $L = E_{x\sim D, y\sim \pi_{\theta}(y|x)}[r_{\phi} - \beta D_{KL}[\pi_{\theta}(y|x) || \pi_{ref}(y|x)  ]  ]$，它是越大越好的
2.  现在我们有两个样本 win 和 lose。我们希望 win 的 loss 比 lose 的尽可能的大。一个很直观的方法就是让着两个loss 作差。因此有 $L_{win} - L_{lose} = r_{win} - r_{lose}  + \beta (\log\frac{\pi_{\theta}(y_{lose}|x)}{\pi_{ref}(y_{lose}|x)}) -  \log\frac{\pi_{\theta}(y_{win}|x)}{\pi_{ref}(y_{win}|x)} )$
3.  可以看到，最大化左侧有两条路径（简化下，只关注其中某一个）

1.  一条是直接最大化 win 和 lose 的奖励差值而忽略掉正则化部分，这很容易导致模型学偏了，远离初始模型，而且 PPO 重要性采样对这玩意也是有要求的，而且 DPO 的目标就是干掉奖励项
2.  另一条路就是让模型即使在拿到相同奖励的时候，win 偏离初始模型比 lose 偏离的小。看着合理哈。。。这样约掉奖励项后（DPO的目标就是干掉奖励项），Loss 就变成了最大化 $Loss = - \beta (\log\frac{\pi_{\theta}(y_{win}|x)}{\pi_{ref}(y_{win}|x)} - \log\frac{\pi_{\theta}(y_{lose}|x)}{\pi_{ref}(y_{lose}|x)}))$
3.  完整的正常推导 见 [人类偏好对齐](https://www.yuque.com/yuqueyonghuyit3fz/ni7q4d/wivigdzy2g92rtnv)

# 参数高效微调

> [2.1 大模型高效参数微调技术](https://www.yuque.com/yuqueyonghuyit3fz/ni7q4d/fvnli2ny0mlaf3gk)

1.  什么是高效微调（PEFT）？

1.  固定住PLM的大部分参数，仅调整模型的一小部分参数来达到与全部参数的微调接近的效果

2.  PEFT 的优缺点？

1.  优点：

1.  能减少内存占用：仅对一小部分参数进行修改，其余参数固定
2.  全量微调会损失模型多样性，存在灾难性遗忘问题，PEFT仅修改小部分参数，模型主题的通用能力还在
3.  降低部署和存储成本，不用每个领域/任务都保存一份副本
4.  根据[论文](https://arxiv.org/abs/2304.14999)，在中低资源(100/1000条数据)情况下，PEFT技术的收敛速度要比全参微调慢。当数据量充足时，PEFT收敛的反而更快。

1.  可能原因是：在较低的数据量下，完全微调迅速学习并过度适应较小的数据集，而PEFT方法的学习是不稳定的，而在较高的数据量下，PEFT方法更稳定，能更好地学习基础数据结构。

2.  缺点：

1.  性能没有全量微调好：虽然都说匹配全参微调，但实际上大部分场景还是差一些的
2.  架构不通用：对新出的模型架构不适配，需要自己修改代码
3.  任务通用性：一些前缀匹配可能只对特定任务生效，换任务需要换前缀重新做

3.  简单介绍下你知道的 PEFT 方法？

1.  Prefix Tuning、**Prompt Tuning**、**P-Tuning、P-Tuning V2**、**Adapter Tuning**、LoRA、AdaLoRA、QLoRA

9.  介绍下 Prefix Tuning 、用途及其优缺点

1.  为LM添加可训练，任务特定的前缀，这样就可以为不同任务保存不同的前缀，微调成本也小；同时，这种Prefix实际就是连续可微的Virtual Token（Soft Prompt/Continuous Prompt）。这些 vitual token 后在Prefix层前面加了MLP结构（重参数化，这是因为PLM得到的 loss 比较小，不重参数化的话，小loss 优化不动
2.  相比离散的Token，更好优化，效果更好。训练的时候只更新Prefix部分的参数，而PLM中的其他部分参数固定。

1.  简单总结下改动点：1. 输入是加前缀向量 [PREFIX; x; y]。 2. 前缀向量后面加一个 MLP 做重参数化。3. 每一层的 key 和value之前都加前缀（再乘上不同的MLP）

12.  介绍下 Prompt Tuning 、用途及其优缺点

1.  prefix tuning 的简化版本，只在输入上拼接，不同的任务，不同的prefix 输入
2.  Prompt token 的长度在20左右时的表现已经不错（超过20之后，提升Prompt token长度，对模型的性能提升不明显了），同样的，这个gap也会随着模型参数规模的提升而减小（即对于超大规模模型而言，即使 Prompt token 长度很短，对性能也不会有太大的影响）。

13.  Prompt Tuning 和 prefix tuning 看着很像，二者的区别是啥？

1.  prompt tuning 更像 hard prompt 对应的 soft 方案，在加的位置上不限于开头，像 prompt 一样加在任意位置。
2.  移除了重参数化的 MLP
3.  其余都是结构上的区别，整体算是 prefix tuning 的简化版

-   为啥 prompt tuning 不需要再每层都加？输入也不需要加 MLP？二者的结论存在冲突怎么理解？

-   答：任务不同，P tuning 的论文证明，**NLG 任务重参数还是需要的，NLU 任务不需要**

14.  介绍下 P-Tuning 、用途及其优缺点

1.  将Prompt转换为可以学习的Embedding层，并用MLP+LSTM的方式来对Prompt Embedding进行一层处理
2.  相比Prefix Tuning，P-Tuning加入的可微的virtual token，但仅限于输入层，没有在每一层都加；另外，virtual token的位置也不一定是前缀，插入的位置是可选的。

15.  介绍下 P-Tuning V2 、用途及其优缺点

1.  该方法在**每一层都加入了Prompts tokens作为输入**，而不是仅仅加在输入层。这导致更多的可学习参数和对模型更深层次的影响。
2.  移除了重参数化、针对不同任务采用不同的提示长度。

1.  针对简单任务：如情感分析，较短的Prompt（~20）即可取得不错的效果。
2.  针对复杂任务：如阅读理解，需要更长的Prompt（~100）。

16.  P tuning V2 和 Prefix tuning 的区别与联系：

1.  在P-tuning v2文章中有说，它的思想并不是最新的，继承自 prefix-tuning。但Prefix-tuning主要设计用于NLG，而P-Tuning v2则是改进后也可以用于NLU了
2.  针对 NLU 任务，去除 LSTM 的重参数化部分

17.  Lora的原理和存在的问题讲一下？

1.  原理：将模型要优化的参数变更用两个低秩矩阵 BA 来表示 ，第一个矩阵A负责降维，第二个矩阵B负责升维，中间层维度为r。在下游任务训练时，固定模型的其他参数，只优化新增的两个矩阵的权重参数，将PLM跟新增的通路两部分的结果加起来作为最终的结果（两边通路的输入跟输出维度是一致的），即h=Wx+BAx。在推理时，将左右两部分的结果加到一起即可，h=Wx+BAx=(W+BA)x，所以只要将训练完成的矩阵乘积BA跟原本的权重矩阵W加到一起作为新权重参数替换原本PLM的W即可，对于推理来说，不会增加额外的计算资源。
2.  用低秩矩阵替代就没代价么？要是没代价的话，训练的时候，W 直接也低秩表示多好？很多全连接层的权重矩阵都是满秩的。当针对特定任务进行微调后，模型中权重矩阵其实具有很低的本征秩（intrinsic rank），因此，论文的作者认为权重更新的那部分参数矩阵尽管随机投影到较小的子空间，仍然可以有效的学习，可以理解为针对特定的下游任务这些权重矩阵就不要求满秩。

18.  LoRA 的特点：

1.  低秩适应：LoRA通过对大型语言模型的参数矩阵进行低秩分解，将其分解为较小的矩阵的乘积。这样可以减少模型的参数量和计算复杂度，提高模型的效率和速度。
2.  减少存储需求：低秩适应可以显著减少大型语言模型的参数量，从而降低模型的存储需求。这对于在资源受限的设备上使用语言模型非常有益。
3.  可扩展性：LoRA的低秩适应方法可以应用于各种大型语言模型，包括预训练的Transformer模型等。它是一种通用的技术，可以适应不同的模型架构和任务

19.  LoRA权重是否可以合入原模型？

1.  可以

20.  LoRA微调方法为啥能加速训练？

1.  LoRA 理论上计算复杂度和全参微调相当（主干模型前向计算+主干模型梯度(算了 W=W0+AB的梯度，但主干梯度不需要保存 + LORA部分的前向+梯度)。所以理论上训练速度差不多，
2.  但实际上实测快10%，为啥？1. 使用LoRA时，我们可以对主干模型进行低精度的量化，如int8或int4，这样可以减少主干模型的前向传播和反向传播的耗时。 2. 使用多卡训练（数据并行）时，我们只需要同步LoRA模型部分的梯度，这样可以大大减少卡间通信的压力，也可以提高总训练速度
3.  LoRA 理论上显存占用比全参微调更低（主要来组主干模型优化器部分），chatglm3 6B 实测低25%

21.  如何在已有LoRA模型上继续训练？

1.  合并权重后继续正常训练

22.  LoRA 缺点是什么？

1.  LoRA 的核心假设是增量矩阵式低秩的。但对于多样性大，数据分布广的训练数据，低秩条件可能不被满足，此时效果会比全参微调差
2.  参与训练的模型参数量不多，也就百万到千万级别的参数量，所以效果比全量微调差一些

23.  介绍下 QLoRA(量化 LoRA)

1.  QLoRA 是模型本身用4bit加载，训练时把数值反量化到bf16后进行训练，LoRA 锁定原模型参数不参与训练，只训练少量LoRA参数，使得训练所需的显存大大减少。
2.  怎么量化到 4bit 的？1. 分位量化(从大到小排序，然后16等分)。 2. 分 block 量化: 不是所有参数一起量化，而是分 block
3.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-27.png)

24.  介绍下 AdaLoRA

1.  LoRA 的所有低秩矩阵秩都相同，但实际上不同层的秩是不一样的。所以 AdaLoRA 对每个模型通过 SVD 的形式参数化增量更新。(低秩矩阵从AB 变成 A\\Sigma B 这种 SVD 形式，根据特征重要性找到合适秩的大小）

1.  大模型为什么会存在幻觉问题？

1.  自回归训练方式，导致大模型在没有真正理解的情况下模仿训练数据，这种随机模仿会导致幻觉
2.  top-k 和 top-p 的采样技术也可能导致幻觉。LLM倾向于产生滚雪球般的幻觉，以保持与早期幻觉的一致性，即使在“Let’s think step by step”这样的提示下，它们仍然会产生无效的推理链

2.  常见的幻觉有哪些？

1.  输入冲突幻觉：LLM 生成的内容与用户提供的源输入不一致
2.  上下文冲突幻觉：LLM生成的内容与之前生成的信息相矛盾
3.  与事实相冲突的幻觉：LLM生成的内容不符合既定的世界知识

3.  [幻觉怎么评估](https://mp.weixin.qq.com/s/i9qaaqWwBMoac8dJLeTvzQ)？

4.  LLM 存在模型幻觉问题，请问如何处理？

1.  比较重要的方法是 RAG、通过反馈自我完善、提示微调、更新模型框架来减轻幻觉
2.  RAG 方案：

1.  RAG通过利用外部权威知识库来增强LLMs的回应，而不是依赖于潜在过时的训练数据或模型内部的知识。RAG不仅可以生成相关和实时的回应，还可生成可验证的回应，有效地减轻LLMs中出现的幻觉问题。
2.  按照检索发生的时间，分为 文本生成之前、生成中。生成之后、端到端四种

1.  文本生成之前：

1.  **LLM-Augmenter**：[Check Your Facts and Try Again: Improving Large Language Models with External Knowledge and Automated Feedback](https://arxiv.org/abs/2302.12813)
2.  当接收到用户查询，该框架首先从**外部知识中检索证据并构建证据链**。然后，使用整合证据的提示向GPT-3.5提问，生成基于外部知识的候选响应。**LLM-Augmenter验证候选响应的真实性**，若产生虚假证据，则**生成反馈信息**用于修订提示并重新提问。此过程持续迭代，直至候选响应通过验证并发送给用户。

1.  从外部知识检索证据的策略是啥？

1.  基于用户的查询（q）和对话历史（hq），生成一组搜索查询
2.  使用这些搜索查询调用不同的API，从各种外部知识源检索原始证据（用 Bing 搜索差维基百科、Reddit等网络结果，还有特定任务数据库）
3.  实体链接器将检索到的原始证据与相关上下文进行丰富，形成证据图谱。
4.  证据链器从证据图中修剪不相关的证据，并形成与查询最相关的简短证据链列表。这些证据链将被发送到工作记忆模块。
5.  知识巩固器（Knowledge Consolidator）将检索到的原始证据与相关上下文链接，并**执行推理以形成证据链**。这个过程可能涉及到将检索到的证据与用户查询相关的实体或主题进行关联。
6.  LLM-AUGMENTER使用包含已巩固证据的提示查询固定LLM（例如ChatGPT），以生成基于外部知识（证据）的候选回答。
7.  如果候选回答包含幻觉证据，LLM-AUGMENTER将生成反馈消息，并使用该消息来修订提示，然后再次查询LLM。这个过程会一直迭代，直到候选回答通过验证并发送给用户。

2.  怎么构建出的证据链？有例子么？

1.  检索：系统首先检索与“2013 Los Angeles Galaxy”和“international titles”相关的信息
2.  实体链接：将“2013 Los Angeles Galaxy”链接到相关的Wikipedia页面或其他数据源，找到与该球队相关的球员转会信息。
3.  证据链形成：系统发现Juninho是从São Paulo转会到Los Angeles Galaxy的球员，而São Paulo拥有12个国际头衔。这形成了一条证据链。

3.  回答验证问题：让LLM依次回答每个验证问题，然后将答案与原始baseline答案进行对比，以检查是否存在不一致或错误。论文里有四种方法：

1.  联合法：通过一次prompt让LLM同时完成提问和回答；即第二步构造的提示示例中同时包含括验证问题及其正确答案，让模型同时生成验证问题和验证问题的答案。
2.  两步法：将验证和回答分为两个独立的步骤，每个步骤都有自己的LLM提示。第一步基于baseline答案进行提问，第二步回答验证问题，但不包含原始baseline答案，以避免互相干扰。
3.  分解法：将所有问题作为单独的Q让LLM独立回答，不包含原始baseline答案。消除了来自baseline答案和验证问题答案之间的潜在干扰。
4.  分解+修订法：在LLM回答验证问题后，输入原始的baseline答案以及模型自我提问回答的Q-A对，让模型检查是否存在不一致的地方![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-33.png)

2.  **自然语言推理链 (CoNLI)** ：[Chain of Natural Language Inference for Reducing Large Language Model Ungrounded Hallucinations](https://arxiv.org/pdf/2310.03951)

1.  自然语言推理链 (CoNLI) 框架通过自然语言推理（NLI）的链来实现幻觉的检测和通过后续编辑来减少幻觉
2.  流程：

1.  分割和选择：将LLM原始相应分割成单独的句子，同时删除那些被认为是噪声或者缺乏用于判断的事实信息的句子。
2.  句子级别检测：将源文本（source text）作为前提（premise），对每个假设（hypothesis，即生成的句子）进行分类（蕴含、矛盾、中立，其中矛盾和中立被认为是幻觉）
3.  实体级别检测：对上一步认为是蕴含的句子，再来一遍实体级别的检测
4.  合并上面的句子级别和实体级别的检测结果
5.  利用上一步的检测结果，对原始相应进行重写来减少幻觉

3.  **ChatProtect**：[Self-contradictory Hallucinations of Large Language Models: Evaluation, Detection and Mitigation](https://arxiv.org/pdf/2305.15852)

1.  在各种指令调整的语言模型（如ChatGPT）中，自相矛盾的情况普遍存在，例如ChatGPT生成的所有句子中有17.7%是自相矛盾的。该方法主要关注LLM生成的自相矛盾幻觉，即在同一上下文中出现逻辑不一致的句子，并提出三步流程来推理自相矛盾，此方法基于提示策略，适用于黑盒LLM，无需外部知识。
2.  检测矛盾的步骤：

1.  使用适当的约束条件生成相关的句子对，以便触发自相矛盾。
2.  使用不同的提示策略来检测自相矛盾。这涉及到自然语言推理（NLI）的技巧，预测两个句子之间的关系是蕴含、中立还是矛盾。
3.  要求分析器语言模型（aLM）首先提供解释，然后给出结论。这有助于将复杂的矛盾检测问题分解为更小的推理步骤。
4.  检测结果是二元的，即句子对是矛盾的或不是矛盾的。

3.  缓解矛盾：

1.  通过迭代过程逐步移除文本中的自相矛盾信息。对于检测到的每对矛盾句子，使用aLM进行局部修订。在修订过程中，尽量保留非矛盾信息，并保持文本的连贯性。
2.  在迭代过程结束后，如果仍有少量自相矛盾被检测到，将相应句子从文本中移除，通常不会影响文本的整体质量。

4.  Mind’s Mirror：为解决小型语言模型（SLM）中的幻觉，本方法将LLM自我评估能力融入到SLM中的精炼过程,将多个不同的CoT和自我评估范例结合在一起，进行全面知识转移到SLM中。
5.  MixAlign：利用语言模型实现自动对齐，通过用户澄清增强对齐。专注于利用基本知识进行忠实决策。在不确定或证据不清时，MixAlign会生成问题，寻求用户澄清，即人为辅助知识对齐。

1.  怎么量化 LLM 中的幻觉程度？

1.  假设LLM 对同一个问题有多个生成，它们间的表述可能不同，但内涵式一样的。因此用 蕴含 （矛盾检测）模型（句子级别 SummaCzs，一个 RoBERTa 的多语言语义蕴含模型）来两两检测句子间的矛盾得分。最终取这里面得分最高的作为一致性分数，得分最低的作为不一致分数

2.  怎么给 LLM 加知识？

1.  作者用的是 实体摘要和三元组。然后一起塞给模型， SFT 微调

3.  大模型怎么指导小模型来提升小模型效果：

1.  大模型用 COT prompt ，得到详细拆解讲解
2.  让模型用这个详细拆解进行输出，如果一致性检测不行，那就让大模型对此提出改进建议，来指导小模型修正输出

2.  幻觉增强复述：该方法引入了LLMs中的属性概念，以控制信息来源并增强事实性。利用LLM幻觉创造对照数据集微调模型以增强模型属性，即使是在训练数据集和模型尺寸较小的情况下，也能超越在事实数据集上训练的模型。
3.  **事实性微调**：该方法采用自动事实检查方法和基于偏好的学习方法，在不需要人工标记的情况下对Llama-2模型进行了事实性微调，显著降低错误。
4.  BEINFO：通过行为微调增加信息，寻求对话中生成的回应的忠实度。模型在包含真实知识来源的大量对话及从大型知识库中随机采样的事实的扩展上进行微调。
5.  拒绝意识指导调节（R-Tuning）：[R-Tuning: Instructing Large Language Models to Say ‘I Don’t Know’](https://arxiv.org/pdf/2311.09677v2)

1.  该方法构建拒绝的训练数据，教会LLM在遇到超出其能力的问题时保持沉默。

6.  深思并有效表达知识 （TWEAK）：该方法将每个步骤生成的序列及其后续序列视为假设，并根据每个生成候选者与输入事实相关的假设程度，利用假设验证模型（HVM）对其进行排名。该方法仅对解码过程进行微调，而无需重新训练生成模型。

9.  强化学习

1.  对齐阶段的目标就是让大模型能够在helpful、honest和harmless等方面与人类价值观对齐，通常训练一个reward模型来评价文本在这几个方面的得分，并采用PPO算法不断地优化SFT模型。 在RLHF阶段缓解幻觉的简单思路就是单独再设计一个针对幻觉的reward score，并直接在RLHF阶段优化即可

1.  缺点：可能会让模型过度“保守”（over-conservatism），过度避开回答一些大模型本身知道的问题，或者重复生成等问题；

# 大模型知识注入

> [Domain Specialization as the Key to Make Large Language Models Disruptive: A Comprehensive Survey](https://arxiv.org/pdf/2305.18703)

![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-45.png)

1.  什么是知识注入？

1.  知识注入是一种将外部知识整合到语言模型中的方法，以提高模型在特定领域任务上的表现。这通常通过在预训练或微调阶段将知识图谱中的信息注入模型来实现。

2.  为什么需要知识注入？

1.  模型训练周期长，而现实世界每天都会有大量新知识的产生
2.  不可能在一个大模型里覆盖所有的领域知识：训练数据可能覆盖通用常识和领域高频知识，但小领域或者领域长尾知识 在训练时可能没有
3.  重新训练的计算成本和效果不确定性：

1.  将LLM适应下游任务需要大量高质量的、特定于任务的数据。获取、清理和预处理这些数据可能是耗时和资源密集型的。
2.  此外，LLM的极端复杂性使得确定最合适的下游任务学习策略具有挑战性，因为超参数的选择、学习率和培训持续时间可以显著影响模型的性能。
3.  LLM的下游任务学习可能导致严重的灾难性遗忘

3.  怎么判断是否需要 continue pre-train

1.  大模型的知识来自于pre-train阶段，如果你的领域任务数据集与pre-train的数据集差异较大，比如你的领域任务数据来自公司内部，pre-train训练样本基本不可能覆盖到，那一定要进行continue pre-train。如果你的领域任务数据量较大（token在1B以上），并只追求领域任务的效果，不考虑通用能力，建议进行continue pre-train。

4.  大模型下，对垂直领域有必要从头训练一个大模型么？

1.  首先看 base 大模型的能力

1.  如果大模型覆盖了垂直领域的绝大部分知识，那没有必要从头训练，只需要微调，让模型学习输出方式即可
2.  如果大模型覆盖了领域基本常识，但很多细节不知道，那可以用 RAG + 微调的方式，让模型通过外挂知识解决
3.  如果领域知识过多或过于复杂，大模型没有包含，那需要继续预训练

2.  但基本上不建议从头预训练大模型

5.  如何给LLM注入领域知识 [综述论文](https://arxiv.org/pdf/2305.18703)？

1.  分类方案是对模型的使用程度，即外部增强（不涉及访问模型参数和梯度等信息）、prompt crafting（可能涉及使用梯度/loss 信息构造prompt）、模型微调（直接改模型参数）
2.  外部增强（RAG 和 agent 那一套）：

1.  领域知识增强：通过从外部知识源中检索特定领域的信息来丰富LLMs的回答，重点是判断知识是否相关

1.  使用显式的知识（能被明确定义的，容易结构化的知识）：

1.  RAG 那一套，知识一般以文档、知识图谱或参数化知识存在
2.  难点是怎么判断检索回来的知识的有效性，以及与 LLM 自身知识冲突时的怎么办
3.  论文1：Few-shot learning with retrieval augmented language models：

1.  检索器：query 和 doc 用 encoder 编码，根据向量相关性取 top k

1.  检索器的训练 loss：

1.  认为 LLM 的 attention 可以指导检索器，因此检索器对 topk 的分布应该和 attention 的分布对齐，因此这俩的 KL 散度作为loss，训练检索器时大模型不更新
2.  检索器的p(d|q) 概率和LLM 的困惑度相乘，约等于这俩绑定了，检索器的检索要让LLM困惑度尽可能的低，训练检索器时大模型也不更新

2.  训练任务：检索器和LLM 联合训练（有点像 BERT）

1.  Masked language modeling

1.  LM：15%的长度为3的token mask掉预测
2.  检索：用mask的token当作query，检索对应的段落

2.  Title to section generation

1.  LM：用维基百科titile和子title，生成对应章节
2.  检索：并用titile和子title检索对应章节

2.  检索器和 LLM 的配合确实是一个点，单独优化 vs 联合优化？能提升多少？

4.  论文2：Rethinking with Retrieval: Faithful Large Language Model Inference

1.  论文改进点：基于从经过思维链（CoT）提示中获得的分解推理步骤来检索相关的外部知识
2.  使用CoT生成一组推理路径Ri（生成多条）
3.  对于每个Ri，应用BM25算法从知识库中抽取相关度最高的10个段落
4.  使用预训练的MPNet模型，通过计算向量相关性来选择最相似的段落
5.  使用预训练的NLI模型，获得每个句子的蕴含（entailment）和矛盾（contradiction）分数
6.  据推理路径解释中所有句子的蕴含分数，矛盾分数和MPNet相似度，使用公式计算每个推理路径的可信度
7.  选出每个问题的最终预测结果

2.  使用隐式知识（一般以向量化存在，包含向量）

1.  比较抽象看着，知识用向量存储，然后这个向量与模型通过 attention进行交互最终转化为输入。。。。你要是向量->文本。。。

2.  领域工具增强：将LLMs与特定领域的外部系统或工具集成，通常通过API进行

1.  LL 调用外挂工具
2.  大模型集成外部领域工具

3.  prompt 工程（可以看 [Pre-train, Prompt, and Predict: A Systematic Survey of Prompting Methods in Natural Language Processing](https://arxiv.org/pdf/2107.13586.pdf)）：

1.  离散 prompt：人类可读的文字模板

1.  prompt mining：从维基百科等大语料文本里找包含输入文本x 和标记 y 的文本，利用本文中间词或依赖路径来制作模板，如 [X] 中间词 [Z]
2.  prompt paraphrasing：用翻译 、同义替换的方式生成
3.  Gradient-based search（[海狸同学：论文阅读：AutoPrompt](https://zhuanlan.zhihu.com/p/432575444)）：用梯度的方法，寻找与梯度方向相同且使梯度下降最快的 token 模板
4.  Promot generation：指定在模板中插入模板标记的位置，为 T5 模型提供解码模板标记的训练样本，最终用 T5 生成模板标记（tokens）
5.  Prompt scoring：使用 LMs 为输入三元组设计了一个模板，行程一个 prompt，而后使用单向 LM 对已填写的 prompt 进行评分，选择 LM 概率最高的 prompt，为每个单独的输入生成自定义模板。

2.  连续 prompt：使通过 embedding 方式做 prompts。这样做有两个显然的好处：① 放宽模板词的语言限制。②取消模板由预先训练的LM参数参数化的限制，模板有自己的参数，可以根据下游任务的训练数据进行调整

1.  Prefix Tuning（[海狸同学：论文阅读：Prefix-Tuning](https://zhuanlan.zhihu.com/p/422249625)）：比如自回归语言模型，prefix 先在输入钱加一个前缀矩阵 z=[PREFIX;x;y], encoder-decoder 的就是 [PREFIX;x;PREFIX';y]。Prefix-tuning 通过初始化可训练矩阵 来存储 prefix 参数。训练目标和 fine-tuing 相同，但语言模型的参数固定，只迭代 prefix 矩阵的参数，这个参数矩阵可以看做一个 prompt 模板
2.  Tuning Initialized with Discrete Prompts：使用离散prompt搜索方法创建或发现的 prompt 来初始化对连续 prompt 的搜索

4.  模型微调（直接看微调部分）：

1.  adapter-based 微调：通过在 LLM 中插入少量额外参数（即适配器）来增强模型在特定任务上的性能

1.  LoRA
2.  其他的

2.  task-oriented 微调：直接更新LLM的核心参数，以更好地适应特定任务

1.  指令微调
2.  部分知识更新：只更新与特定领域或任务相关的部分参数

6.  如何给LLM注入领域知识？（简单回答版）

1.  使用 prompt 将外部知识组合进 LLM 输入中

1.  涉及如何设计/优化 prompt
2.  怎么召回相关知识

2.  微调模型

1.  LoRA 高效微调 或者就正常 SFT

3.  全量预训练 base 模型，而后再对齐

1.  领域数据 + 通用数据混合，直接continue pre-train

7.  大模型的微调如何避免过拟合？

1.  首先避免盲目微调：数据集质量很低或者量很少的话，尝试优化 prompt ，采用 one-shot 或 COT 的方式来提升模型表现
2.  避免盲目加大数据规模：大量重复模式的数据不会提供很多有用的新信息，反而会导致模型过拟合到重复模式上
3.  小学习率微调：大的学习率会对已有模型空间进行破坏，使其过拟合
4.  使用正则化技术(比如加入和初始模型的 KL 散度 loss），控制参数更新幅度
5.  常识专家网络：路由优化，不同的专家负责不同的任务，能降低过拟合风险

8.  大模型的微调如何避免对通用知识的遗忘？

1.  微调时加入通用领域知识，像链家的论文，配比 1：5（通用5），还有其他论文配比 1：10 的
2.  配合 prompt 优化：合理的 prompt 能够减少对其他 prompt 任务的性能损失
3.  冻结预训练参数，减少模型需要更新的参数数量，比如各种高效微调方案
4.  小学习率微调：大的学习率会对已有模型空间进行破坏，使其过拟合
5.  专家网络模型：base 模型用专家网络，能够减少对通用能力的损害

# 大模型的知识编辑

> [Knowledge Editing for Large Language Models: A Survey](https://arxiv.org/pdf/2310.16218)

## 知识编辑

1.  什么是知识编辑？

1.  更新模型里的错误 / 过时的知识，如 训练时的美国总统是奥巴马，但实际用的时候变成了 特朗普。这总不能直接重新训练。这就需要用到知识编辑。

2.  知识编辑和微调的区别？

1.  二者都希望能改变模型的输出，但：

1.  局部性：知识编辑更看重修改特定的知识，同时保持模型对其他知识的输出不变或影响尽可能小
2.  泛化性：知识编辑希望能改变所有涉及到该知识的场景输出

3.  知识编辑的衡量指标是什么？

1.  编辑分数(Editing Score, ES)，包含：

1.  Efficacy Success(ES)：编辑成功分数（生成中，新目标词的概率大于原目标词的概率）
2.  Paraphrase Success(PS)：同义表达成功分数（对同义表达,仍然成功的比例）
3.  Neighborhood Success(NS)：非同义成功保持分数（对没有修改的知识保持成功的比例）
4.  上面三个分数的调和平均数就是编辑分数

4.  知识编辑有哪些常见方案？

1.  外部记忆化：外部记忆化方法通过引入外部存储来保存新知识，而不需要修改预训练模型的权重，可以完整地保留LLMs中的预训练知识，并且由于存储容量的可控性，使得新知识的整合变得灵活且可扩展。

1.  **纯外挂知识：通过 ICL 等方案，使用相关性判别器判断问题/模型原答案是否涉及到外挂知识，如果涉及到了就把外挂知识放到 ICL 中/预设的 prompt 里，引导模型使用新知识。**
2.  在模型的一部分结构里添加适配器：看着很像高效微调啊。。。只不过改动很小，比如在最终的 FFN 输出上加了些参数来进行适配。看着不咋靠谱

2.  全局优化：对全部参数进行训练，但加了约束来限制对其他预训练知识的负面影响

1.  **约束微调 Constrained Fine-tuning：**

1.  **约束1，新旧模型的 loss 作为正则项，简化版就是参数的范数作为正则项(但效果堪忧)，是论文 Modifying Memories in Transformer Models 提出的**
2.  约束2，在 FFN 层，使用 LoRA，然后判断输入是否和目标知识相关，相关的话走 LoRA 后的部分，否则走之前的（是个办法）

2.  中间微调 Intermediate Fine-tuning：

1.  使用小型的超网络（Hyper-Network）作为中间模型来生成主网络的权重，从而高效地进行参数更新。比如网络的参数是 10000x10000，现在用一个 10000x10 + 10x10000 的网络做两次线性化，就可以生成较大的参数。这个小网络生成的参数可以看做新知识对旧网络的影响。有点像 LoRA 啊，但感觉有两个问题：1，小网络生成大网络参数看着有点不靠谱啊，2.知识多的时候，小网络能承载住么？
2.  特定于任务的超网络（即基于任务属性生成目标模型权重的网络）在缓解灾难性遗忘问题方面是有效的。

3.  **局部修改**：在LLMs中定位和修改特定知识的相关参数，以整合与编辑相关的新知识

1.  这东西感觉也是会影响全局的吧，一层一层间的依赖本来就很玄学。。。
2.  当前研究认为知识存储在 FFN 层中，这个说法流行的比较久了倒是。论文提供了一个有意思的解释。。。self-att 的公式是 $seft-att(x) = Softmax(q_{i}k_{i}^{T})v_{i}$，FFN 的公式是$FFN(h) = GELU(hW_{1})W_{2}$。对比下俩公式， FFN 里面的 h 就像是 q，W1 就是k，W2 对应着v。整体就像是去 W2 里检索了下信息。
3.  怎么定位要修改的参数？

1.  令某个FFN 的w权重从0到正常值变化，选取累计概率最高的w 认为和该知识相关
2.  直接修改一层：将安全回答和黄暴回答分别在预测阶段输入大模型，分析 |H\_safe - H\_unsafe| 最大的那一层，认为是导致黄暴的原因层，针对这一层重新 sft 训练，同时固定其它层。训练时再加上个 loss，使得网络对正常输入的变化影响尽可能小（训练前后正常回答的 KL 散度）-- Detoxifying Large Language Models via Knowledge Editing
3.  因果启发方法：用causal tracing找重要hidden states，判断information flow，代表性工作有 ROME、MEMIT、PMET 方法。

1.  [ROME - Locating and Editing Factual Associations in GPT](https://arxiv.org/pdf/2202.05262) 举例

1.  定位重要知识神经元：

1.  首先输入 prompt，比如：“The Space Needle is located in the city of" ，GPT将会输出 Seattle。此时保存下模型内部的hidden state。
2.  重新输入上述prompt，在embedding层增加随机噪声。此时模型内部的hidden state应该都有错误了
3.  对step 2中的每个神经元，逐一使用step 1中的hidden state进行恢复（每次只有一个神经元的hidden state是正确的），看模型的输出Seattle的概率变化。
4.  作者发现 早期 MLP 贡献大，后期 attention 贡献更重要

2.  编辑知识神经元 - 修改权重 W：

1.  K 由多次输入同义的prompt，然后取那个位置的向量的均值得到
2.  V 由反向传播，根据目标输出得到的梯度，求得目标的 V
3.  根据 K 和 V，求 W，其中 WK = V

3.  评价：步骤繁琐，容易崩

5.  知识编辑有哪些常见方案？（简单版/我认为落地可行的版本）

1.  纯外挂知识：通过 ICL 等方案，使用相关性判别器判断问题/模型原答案是否涉及到外挂知识，如果涉及到了就把外挂知识放到 ICL 中/预设的 prompt 里，引导模型使用新知识。
2.  约束微调 :新旧模型的 loss 作为正则项，简化版就是参数的范数作为正则项(但效果堪忧)
3.  搞一个新模型存储新知识：使用 LoRA，然后判断输入是否和目标知识相关，相关的话走 LoRA 后的部分，否则走之前的
4.  局部参数修改：定位存储知识的神经元/层，然后进行针对性训练

## 知识冲突

1.  供给LLM的不同信息源的知识有冲突。
2.  Inter-context conflict（黄色）：retrieved documents之间的信息存在冲突

1.  训练模型去检测两个 doc 间是否存在冲突
2.  用 google 等网络搜索引擎返回的结果，对其中的事实部分进行校验和补充

3.  Context-memory conflict（红色）：retrieved documents和LLM的参数化知识之间存在冲突

1.  要判断是检索回来是对的，还是模型的是对的
2.  检索是对的：

1.  修改 prompt，让模型从输入中选取事实作为答案

3.  模型是对的：

1.  降低检索知识的权重/卡控严格检索结果，非必要不提供

4.  LLM 单独没有倾向信任自身还是外部知识，更倾向于语义连贯、有逻辑、令人信服的信息

4.  Intra-memory conflict（蓝色）：LLM的pretraining data中存在知识冲突，导致pretrain之后参数化知识之间存在冲突

2.  一个复杂的推理任务，其可以有多种推理路径（即解题思路），最终都能够得到正确的答案。故Self-Consistency在解码过程中，抛弃了greedy decoding的策略，而是使用采样的方式，选择生成不同的推理路径，每个路径对应一个最终答案。具体做法为： - 对于单一的测试数据，通过多次的解码采样，会生成多条推理路径和答案。 - 基于投票的策略，选择最一致的答案。

2.  论文继承了 self-consistency 方法，具体来讲：

1.  对于同一个问题，生成多条不同的推理链和答案

7.  Automatic chain of thought prompting in large language models

1.  Auto-COT，具体流程是

1.  对数据集中的 question 进行聚类（先用 sentence-BERT 进行向量嵌入，然后用 k-means 进行聚类，对每个簇中的 question，按照距离中心点的距离升序排列）
2.  在每个簇中选取一个代表性问题（长度短的，推理链不超过5个步骤的）：具体来说用 Let's think step by step 做 zero-shot-COT，得到问题-推理链-答案，然后看是否满长度短，推理链不超过5个步骤的条件
3.  遍历完所有簇，将得到k个demostrations，将其拼接上测试question，构造成新的Prompt，输入LLMs便可得到生成结果。（也就是把第二步得到的结果用作后续的 ICL 了）

11.  Scaling Instruction-Finetuned Language Models

1.  1.增加微调任务数量，可以提高LLM表现。但任务数量超过一定值后，不管模型尺寸是否增大，受益都不大。推测原因有：

1.  额外的任务多样化不足，没有为LLM提供新的知识
2.  多任务指令微调只是更好地激发了模型从预训练任务中学习到知识的表达能力，而微调任务超过一定值后，对表达能力没有太大帮助

3.  微调数据与CoT数据的关系

1.  微调数据中删除CoT数据，会降低PaLM的推理能力
2.  微调数据包含CoT数据，会全面提高所有评测任务的表现
3.  对于大模型LLM涌现的CoT能力，业界目前的共识是：当模型参数超过100B后，在复杂推理任务中使用CoT是能带来增益的；而当模型小于这个尺寸，CoT并不会带来效果增益

8.  [Boosting Language Models Reasoning with Chain-of-Knowledge Prompting](https://arxiv.org/pdf/2306.06427v1)

1.  传统的链式思考（Chain-of-Thought，简称CoT）提示虽然已经取得了一定的成功，但生成的理由经常包含错误，导致推理链不准确或不忠实。为了解决这个问题，CoK提示方法鼓励L**LMs生成以结构化三元组形式显示的明确知识片段作为推理的证据**。这种方法的灵感来源于人类在回答复杂问题前会在大脑中绘制思维导图或知识图作为推理证据的行为
2.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-48.png)
3.  里面的证据三元组（CoK-ET）：这是一系列结构化的三元组列表，用于反映从问题到答案的整体推理证据。每个三元组包含主体（subject）、关系（relation）和客体（object），例如：（Derrick White, isA, basketball player）。
4.  解释提示（CoK-EH）：这是**对推理链的解释**，类似于传统的CoT提示，但CoK-EH更注重于解释证据三元组如何支持最终答案。下面看 CoK-EH 是怎么生成的，大体来讲就是现对 原始 question 生成答案 A，将 A 向量化后去计算最相关的 K 个知识三元组，然后用专家对知识三元组进行过滤得到干净的证据三元组。最终得到多个不同的标注示例。

1.  选择基础示例：首先从训练集中随机选择一些标记好的示例作为基础的示例（exemplars）。
2.  生成文本推理链：使用零样本CoT（Zero-shot Chain-of-Thought）方法，通过在输入查询后附加一个简单的提示，例如“Let’s think step by step”，来引导LLM生成推理链和最终答案。这一步不涉及证据三元组的生成，而是专注于生成推理过程的文本描述。
3.  编码文本推理链：将生成的文本推理链编码，通常使用基本的句子编码器（如BERT模型）来获得其表示形式。
4.  检索候选三元组：使用编码后的文本推理链，通过最大内积搜索工具（如SCaNN）从预构建的知识库中检索最相关的知识三元组。
5.  手动设计证据三元组：由于检索到的三元组可能包含噪声和冗余信息，研究者邀请领域专家（如教授和博士生）基于检索到的三元组手动设计证据三元组。
6.  自训练提高效率：为了提高注释效率，可以采用自训练的思想，即基于很少的数据生成标注数据。首先手动注释少量数据以形成2-shot CoK提示，然后将其余数据与此提示结合，让LLM生成相应的推理和答案，再由专家进行验证和纠正。
7.  选择最佳提示：生成多个不同的标注示例后，通过在测试集的一个子集上进行评估来选择最佳提示。选择具有最佳准确度的提示作为最终的CoK-EH。

5.  验证事实性和忠实性：

1.  事实性验证：评估生成的三元组和知识库中真实三元组的匹配程度，一个是真实的完全匹配（精确验证），另一个是用图补全任务判断该三元组是否为真（隐式验证）
2.  忠实性验证：用 SimCSE 计算测试查询+证据三元组+最终答案 序列和原始提示之间的相似度

6.  分不够就继续迭代（方案太复杂，适合学术）

3.  对预训练模型和指令微调后的模型，应该分别采用什么评估方案？

1.  预训练 checkpoint 具有 in-context learning 的能力。大多数预训练模型可以进行 in-context answer-only，一些更好的模型可以进行 in-context chain-of-thought（但目前尚不清楚为什么某些预训练模型可以进行 CoT 而其他模型却不能）。然而，预训练 checkpoint 可能无法进行 zero-shot，因为它们没有经过这方面的训练（但某些预训练检查点仍然可以进行 zero-shot CoT）
2.  指令微调过后的 checkpoint 既具有 zero-shot 又有 in-context 的能力。这里需要注意的是，如果没调好，指令微调之后 in-context 性能可能会稍有下降。
3.  整体来讲，建议使用 in-context chain-of-thought 进行评估。

10.  **如何构建基于langchain+向量库的文档对话？**

1.  查询生成

1.  确定查询类型（意图）：首先确定用户可能的查询类型，例如问题查询、主题查询、摘要查询等。针对不同的查询类型，可以构建相应的prompt模板。
2.  确定查询内容（检索域）：根据文档的特点和领域知识，确定用户可能会查询的内容。例如，对于新闻文档，查询内容可以包括新闻标题、关键词、时间范围等；对于学术论文，查询内容可以包括作者、论文标题、摘要等。根据查询内容，可以构建相应的prompt模板。例如，对于查询新闻标题的情况，可以使用"请问有关于XXX的新闻吗？"作为模板。
3.  添加过往上下文信息：考虑上下文信息对于查询的影响。用户之前的查询或系统的回复可能会影响当前的查询。可以将上下文信息加入到prompt模板中，以便更好地理解用户的意图。例如，对于上一轮的回复是关于某个主题的，可以使用"我还有关于上次谈到的XXX的问题"作为模板。
4.  替换可变参数：考虑到用户的查询可能有不同的变化，可以在prompt模板中留出一些可变的参数，以便根据具体查询进行替换。例如，可以使用"我想了解关于XXX的信息"作为模板，其中的XXX可以根据用户的查询进行替换。

2.  文档处理：

1.  数据预处理：首先，需要对文档数据进行预处理。这包括分词、去除停用词、词干化等步骤，以准备文档数据用于后续的向量化和建模。
2.  文档向量化：文档向量化是将文档表示为数值向量的过程。这可以使用向量库技术，如TF-IDF、Word2Vec、Doc2Vec等。文档向量化的目的是将文档转换为计算机可以处理的数值形式，以便计算文档之间的相似度或进行其他文本分析任务。
3.  文档检索：当用户提供一个查询文本时，首先对查询文本进行向量化，然后计算查询向量与文档向量之间的相似度。可以使用余弦相似度或其他相似度度量方法来衡量它们之间的相似程度。根据相似度排序，返回与查询文本最相关的文档。
4.  文档推荐：除了简单的文档检索，还可以使用大语言模型生成推荐文档。通过输入用户的查询文本，使用大语言模型生成与查询相关的文本片段或摘要，并根据这些生成的文本片段推荐相关的文档。
5.  相似度计算：相似度计算是文档对话系统中的重要技术。通过计算查询文本向量与文档向量之间的相似度，可以实现文档的检索和推荐。常见的相似度计算方法包括余弦相似度、欧氏距离等。

3.  答案生成：

1.  引入多样性的生成策略：在生成文本时，可以采用多样性的生成策略来减少模型的倾向性和幻觉问题。例如，使用温度参数来调整生成的多样性，或者使用抽样和束搜索等不同的生成方法。
2.  人工审核和后处理：对生成的文本进行人工审核和后处理是一种常用的方法。通过人工的干预和修正，可以纠正模型幻觉问题，并确保生成的内容准确和可靠。
3.  引入外部知识和约束：为了提高生成文本的准确性，可以引入外部知识和约束。例如，结合知识图谱、实体识别或逻辑推理等技术，将先验知识和约束融入到生成过程中。

10.  怎么优化文档切分？

1.  基础的就是基于换行符、句号等特殊符号的分割。
2.  结合其他工具：除了Langchain内置的问答分句功能，还可以结合其他分句工具或库来处理文本。例如，NLTK、spaCy等自然语言处理工具包中提供了强大的分句功能，可以与Langchain一起使用，以获得更好的分句效果。
3.  使用上下文信息：如果上下文信息可用，可以利用上下文信息来辅助分句。例如，可以根据上下文中的语境和语义信息来判断句子的边界，从而提高分句的准确性。
4.  预处理和过滤：在进行文档切分之前，可以进行一些预处理和过滤操作，以减少噪声的影响。例如，可以去除文档中的停用词、标点符号、特殊字符等，以及进行拼写纠错和词形还原等操作。这样可以降低噪声的存在，提高文档切分的质量。
5.  主题建模：可以使用主题建模技术，如LDA（Latent Dirichlet Allocation）等，对文档进行主题抽取。通过识别文档的主题，可以帮助确定文档切分的粒度。例如，将同一主题下的文档划分为一个切分单元，以保留更多的语义信息。
6.  上下文信息：在进行文档切分时，考虑上下文信息对于语义的影响。例如，将与上一文档相关联的文档划分为一个切分单元，以保留上下文的连贯性和语义关联。这样可以更好地捕捉文档之间的语义信息。
7.  动态切分：可以采用动态切分的方式，根据用户的查询和需要，实时生成切分单元。例如，根据用户的关键词或查询意图，动态生成包含相关信息的切分单元，以减少噪声和提高语义的准确性。
8.  实验和优化：在实际应用中，可以进行一系列的实验和优化，通过不断调整和评估文档切分的效果。可以尝试不同的切分粒度，评估其噪声和语义信息的平衡。通过实验和优化，逐步找到合适的文档切分策略。

11.  如何提升问答在特定领域的表现？

1.  针对垂直领域进行领域特定训练：LLM模型是基于大规模通用语料库进行训练的，可能无法充分捕捉垂直领域的特点和术语。可以使用领域特定的语料库对LLM模型进行微调或重新训练，以提高在垂直领域的表现。
2.  增加领域知识：在向量库中，可以添加垂直领域的专业知识，如领域术语、实体名词等。这样可以提高向量库中文档的表示能力，使其更适应垂直领域的对话需求。
3.  优化检索算法：在使用向量库进行文档检索时，可以尝试不同的检索算法和相似度计算方法。常用的算法包括余弦相似度、BM25等。通过调整参数和算法选择，可以提高检索的准确性和相关性。
4.  数据增强和样本平衡：在训练LLM模型时，可以增加垂直领域的样本数据，以增加模型对垂直领域的理解和表达能力。同时，要注意样本的平衡，确保训练数据中包含各个垂直领域的典型对话场景，避免偏向某个特定领域。
5.  引入外部知识库：在垂直领域的对话中，可以结合外部的领域知识库，如专业词典、行业标准等，来提供更准确的答案和解决方案。通过与外部知识库的结合，可以弥补LLM模型和向量库在垂直领域中的不足。

## Megatron-LM

[megatron学习总结](https://zhuanlan.zhihu.com/p/381326200)

1.  Megatron 的特点

1.  数据(data)并行：将数据集分割成多个部分，模型也复制很多份，每部分数据在不同的GPU上并行处理。

1.  pytorch 里的 DistributedDataParallel，先创建多个进程，每个进程有一个模型，把数据分配到不同的进程上，它负责同步不同的进程的梯度下降，保持不同进程的模型的参数一致（不同的进程分别做 forward 和 backward，而后把不同进程的梯度平均之后返回各个进程再集中更新参数，以此保证模型的一致性）。

2.  tensor并行：把一个神经网络层Tensor切成了多个小的Tensor，每个tensor放在不同的gpu。主要就是列并行、行并行。

1.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-51.png)
2.  一般在 embedding 、FFN、attention 上做并行。![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-52.png)

3.  流水线(pipeline) 并行：将模型的不同层次分布到不同的GPU上，并行处理不同阶段的计算，进一步提高效率。

2.  什么时候用 Megatron ？

1.  相比于 deepspeed，当显卡到几百张这种大规模时，deepspeed 的 zero1/2/3 本质还是 数据并行，卡数上去了以后 all reduce 的通信开销越来越大，而张量并行可以高效利用节点内带宽。流水线并行可以用低通信开销。

1.  ZeRO 原理：ZeRO是一种针对大规模分布式深度学习的新型内存优化技术，分为 stage 1 2 3 。

1.  Stage1：把 优化器状态(optimizer states) 分片到每个数据并行的工作进程(每个GPU)下
2.  Stage2：把优化器状态(optimizer states) + 梯度(gradients)分片到每个数据并行的工作进程(每个GPU)下
3.  Stage3：把优化器状态(optimizer states) + 梯度(gradients) + 模型参数(parameters)分片到每个数据并行的工作进程(每个GPU)下

1.  ![image.png](/img/yuque/计算机/大模型/assets/以_QA_形式看大模型基础知识-54.png)
2.  以最复杂的 Stage3 为例，顺一下流程：

1.  首先模型和数据被拆成4分，被分配到不同的 GPU 上
2.  前向传播开始：

1.  把 M0 的参数分发到 GPU 1,2,3 上，用 Data 0, 1，2，3 分别计算出各自的结果，保存下来，把 GPU 1，2，3 上的参数删掉
2.  把 M1 的参数分发到 GPU 0，2，3 上，用 Data 0,1,2,3 分别计算各自的结果（接着之前的算），保存下来，把 GPU 0，2，3 上的参数删掉
3.  重复上面的过程，算完 M3 ，此时就可以得到各自的 Loss 了，开始反向传播

3.  反向传播开始：

1.  M3 模型在各个 GPU 上还没删，用loss 计算 M3 的梯度，其他 GPU 把各自的梯度传给 GPU3做累加，最后 GPU 0，1，2 删掉 M3 的梯度和参数 + 激活
2.  类似前向传播，M2 把自己的参数分发出去算 M2 部分的梯度，然后累加，再删除参数、梯度啥的
3.  重复完成后，每个 GPU 都有自己模型部分的梯度了，直接更新参数就可以了。

2.  什么是 param offload？

1.  offload 指将数据、梯度、优化器状态等下沉到CPU内存或硬盘上
