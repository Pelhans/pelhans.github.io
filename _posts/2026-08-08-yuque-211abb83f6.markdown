# 背景

主要挑战：

1.  耗时短，2ms 以内
2.  准确性要求高， 92% 以上
3.  尽可能的捕捉语义信息，难度高：北京市第一中学 、 北京市第二中学

# 方案

地标识别的相关性计算整体上是遵循 字符编辑距离相关性 --> 基于人工特征的 xgb 的方法 --> 基于 pointwise 的方法 --> 基于对比学习的方法 -> 蒸馏 BERT -> BGE类模型 的迭代路径。

## 基于字符编辑距离的相关性

这个阶段主要目标是解决片段链接问题，即：链接片段占 query / entity 的一小部分 和 关键信息 丢失的部分。举个例子，用户搜索 辽宁省沈阳市浑南区飞云路6-1号（辽宁电信东南门），通过片段 辽宁电信 链接到的 实体 中国电信 南京南营业厅 。此时就可以通过字符编辑距离等特征进行解决。

## 基于 pointwise 的 ESIM 方案

基于编辑距离的卡控因为策略较为死板，为了防止误伤，只能解决一小部分线上 case。同时随着运营的评估，地图侧的结果表现优于实体链接的结果，要放开地图结果。伴随着这两点原因，对泛化性更强的策略的需求越来越旺盛。因此提出用语义相关性模型来放开部分地图结果，提升酒店频道内的召回率和准确率。

### 样本构造

从大搜侧，抽取 100 w 条有 address\_info 信息的 query，获取它的点击信息、地标结果信息（entity\_name，entity\_type）、地图结果信息（name、address、type）。

-   点击数大于等于 3 的记为正例。得到 query + entity\_name + entity\_type 对
-   点击数等于 0 的，取地图结果排名 3 - 4 位的地址作为负例。得到 query + lbs\_name + lbs\_code 对
-   过滤掉 where == entity\_name 且点击分次数为 0 的样本。
-   过滤掉 ww 成分 <= 2 的负样本

得到 有效样本: 372532。其中 正样本数量： 59999，负样本数量： 312533，负正样本比例：5.21。

### 特征生产

-   调用 QU 接口获取 where-what 信息、酒店频道 NER 信息、词权重信息。
-   计算 Jaccard 系数、编辑距离、前缀匹配、后缀匹配、词权重占比等特征

### 训练数据

采用 pointwise 的方法构造正负样本。其中正样本是指 where 成分 和 doc 是同一地址，tag 为 1。负样本就是 where 成分 和 doc 不是同一地址，tag 为 0。

### 模型结构

整体模型框架基于 ESIM 模型，选择 ESIM 的原因是对比了 DSMM / CDSSM /MatchPyramid/BiMPM 模型后发现 ESIM 综合了上述模型的优点，在语义编码和特征组合方面都做的比较好。比较重大的缺点就是 LSTM 模型耗时较高，在 DQU 上上线困难。同时在我们的场景中无论 query 还是 poi 的文本都比较短，因此使用 CNN 代替 LSTM 进行语义编码，其余结构未进行大改动。最终该版本在用 C++重写后线上推断平均耗时 0.5 ms。基于 CNN 的 ESIM 模型结构如下所示：

## 基于对比学习的 ESIM 方法

### V1

近两年，对比学习（Contrastive Learning）在计算机视觉领域（CV）掀起了一波浪潮，**MoCo**、**SimCLR**、**BYOL**、**SimSiam**等基于对比学习思想的模型方法层出不穷，作为一种无监督表示学习方法，在CV的一些任务上的表现已经超过了有监督学习。同时，自然语言处理（NLP）领域近来也有了一些跟进的工作，例如**SimCLS**、**ConSERT**、**SimCSE**等模型利用对比学习思想进行句表示学习，在语义文本相似度匹配（STS）等任务上超过了SOTA。

由于第一版模型在构造数据集时采用未点击的样本作为负样本来源，饱受数据噪声的困扰。而对比学习是一种度量学习方法，它更看重拉近相似样本，对噪声的鲁棒性更强。因此我们采用对比学习的方法来构造样本和训练。

#### 样本构造

正样本构造采用数据增强 + 别称数据组合的方式获取。负样本则采用对比学习中的同 batch 内随机采样得到。

-   别称数据：从 sug 那面得到了一批poi 别称数据，这些数据时天然的正样本
-   正样本数据增强：通过观察别称数据，发现简称相对于全poi 是有一定的丢词规律的，因此通过 NER 成分和权重特征，随机丢掉一部分词来得到增强的正样本。对于这种方法得到的正样本，它的负样本相对要求更严格一些（更离谱些）。

最终共得到数据 265,298 条。

#### 模型结构

模型结构和相比于第一版，在 CNN 上做了些改进。第一版网络结构有如下缺点：

-   第一个 CNN 语义编码层只有一层 CNN ，且 核的大小为1，3，5 。这样模型的感受野相当有限，虽然我们的 query 和 doc 是短文本，但也远不能覆盖全文，导致长文本分类效果较差。为了扩大感受野：

-   增加语义编码的 CNN 层数，由 1 扩大到 2 层，且第二层的 核大小为 3，5，7。这样基本上可以覆盖到全文

-   在最后的特征组合处，添加一层 CNN 对特征进行进一步抽象化，得到相对重要的特征；降低特征维度，方便后续分类；

其余未改动。最终该版本在用 C++重写后线上推断平均耗时 0.75 ms。

### V2(不对外讲)

之前的二分类有一个问题是，比如用户搜索万达，万达广场是相关的，但万达广场-停车场就被认为是不相关的了。但当召回里没有万达广场时，万达广场-停车场也是可以作为地标露出的。因此本次迭代将二分类扩充至四分类：

1.  不相关
2.  完全统一个东西，一对一，如名字完全匹配或者独一无二的简称/别称
3.  泛指，这个 query 可以指代这个poi，也可能是其他 poi ，如万达
4.  父子地标，query 和 对应的 poi 是父子关系，如万达广场 - 万达广场停车场

扩充到四分类后，整体准召率提升xx，

## 3层BERT + 对比学习（类似 GTE 的方案）

用酒店业务蒸馏的 miniBERT，进行类似 GTE 的继续两阶段对比学习训练。

1.  第一阶段，通用对比学习

1.  收集训练数据，共收集到数据 520w 条，其中通用 和 领域数据配比 3：1

1.  通用

1.  社区问答：百度知道
2.  百科：维基百科、百度百科

2.  酒店领域

1.  poi - 介绍
2.  poi名字 - poi 简称

2.  通用对比学习设置：学习率 1e-5，batch\_size 4096 \* 8 = 32768
3.  一个正样本和一个难负样本，负样本从 用 es 召回排名靠后的数据作为难负例（10-20 名 与 20 开外数据随机采样）。这一阶段难负样本质量不太行，需要大的 batch\_size

2.  第二阶段，实际分类数据微调

1.  query 向量召回任务的数据：query - 点击、收藏、下单的作为正样本，in-batch 的作为负样本，线上相关性模型最底层的作为难负样本，难负样本有 7 个。整体数据有 2000w 条，batch 4096 \* 8 = 32768
2.  相关性优化任务：sug 别称、简称数据作为正例，大概有100w 条。in-batch 内负采样作为负样本，用 es 召回排名靠后的数据作为难负例（10-20 名 与 20 开外数据随机采样）。在finetune阶段，由于数据集原本的强监督信息跟hard negative，batch size就没有必要设置的特别大

## 从 LLM2Vec 蒸馏到 BGE 上

bge 模型经过了太多轮的对比学习，语义能力存在丢失情况，因此从LLM2vec 蒸馏到 bge 上，同时再做对比学习。这样能较大程度的保留语义能力，提升最终的向量表征效果。

在 query 和 passage 编码后，计算下编码和大模型向量编码的 KL loss。loss 只考虑 query 、正例、负例 的 loss，不考虑 in-batch 内其余数据的（没意义，其他数据会自己算）。最终两个 loss 正产 1：1 相加即可。

​  

LLM2vec 用的 base 模型是 gte-Qwen2-7B-instruct。

​  

最终提升有限，但长难query经人工评估，效果好很多。语义保存度较高。

# 问题

1.  为什么不复用地标召回时的模型去计算相关性？

1.  从用途上看：召回的相关性模型关注召回率，会有多个结果满足召回要求，看重的是覆盖率和有多少候选进入粗排和精排。而相关性模型是二元的，只关注 0 和 1 ，不关注具体分数、排名和后续是否进入粗排和精排
2.  从功能上看：召回可以有很多路，不同的路可能有不同的向量 embedding ，而相关性模型是统一的，多路召回结果会统一过一个相关性模型进行判别
3.  从性能耗时上看：目前地标信号整体耗时大头是召回，约占 15ms/25ms 。剩余的 10ms 还要做混合排序和相关性判别 + 业务适配，时间比较紧，因此相关性部分的模型会简单很多。
