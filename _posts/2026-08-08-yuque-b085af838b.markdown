# 论文解读：Towards a Science of Scaling Agent Systems（2025）

> 一句话总结：本文首次给出 agent 系统的量化缩放定律——在 6 大基准、5 种架构、3 个模型族共 260 组受控实验上证明：多 agent 是否奏效取决于"架构-任务匹配"与"信息冗余/错误放大"，而非单纯堆 agent 数量；当单 agent 基线已超 45% 时，加 agent 反而亏。

## 1\. 背景与动机

2024–2025 年社区流行"更多 agent 更好"的乐观叙事（如 "More Agents Is All You Need"、"Mixture-of-Agents"），但缺乏可预测的定量框架。工程师往往靠直觉堆 agent，结果"demo 里好、生产里崩"。本文（Google Research / DeepMind / MIT）要回答：agent 系统的性能到底随哪些维度缩放？何时加 agent 真的放大性能、何时反而侵蚀性能？它把"协调结构、模型能力、任务属性、agent 数量"统一刻画，试图建立 agent 界的"缩放科学"。

> 说明：你给的暂定标题 "Understanding Agent Scaling via Diversity" 并没有对应某篇单一经典论文；本题核心论点"信息冗余而非协调是瓶颈"最契合的 2025 真实 landmark 即本篇——它把 message density / redundancy / error amplification 作为协调指标，量化了多 agent 扩展为何收益递减。

## 2\. 核心问题

1.  agent 系统性能如何随 agent 数量、协调结构、模型能力、任务属性变化？

2.  什么条件下"加 agent"带来正收益，什么条件下带来负收益（收益递减）？

3.  能否用可测的任务属性，预测出最优的协调架构？

## 3\. 方法与架构

受控实验设计：固定任务提示、工具与计算预算，仅变化协调结构与模型能力。覆盖 **5 种标准架构**（Single / Independent / Centralized / Decentralized / Hybrid）、**3 个 LLM 族**（OpenAI、Google、Anthropic）、**6 个基准**（BrowseComp-Plus、Finance-Agent、PlanCraft、Workbench、SWE-bench Verified、Terminal-Bench），共 **260 组配置**。

用混合效应回归，以实证协调指标作为预测变量建模：

-   efficiency（成功/开销比）

-   error amplification（错误放大倍数）

-   message density 与 **redundancy（冗余度）**

得到跨基准交叉验证 R²=0.373（用任务挂钩的能力指标后为 0.413），并能为 **87%** 的留出配置预测最优架构。

```plain
 agent数量 ─┐
 协调结构  ─┼──► 受控实验 (260 配置) ──► 协调指标(效率/错误放大/冗余) ──► 回归模型
 模型能力  ─┤                                                  │
 任务属性  ─┘                                                  ▼
                                              预测最优架构 (87% 命中)
```

## 4\. 关键实验与结论

-   **工具-协调权衡**（β=−0.096, p=0.002）：工具密集任务（如 16 工具的业务流）承受多 agent 协调开销，效率惩罚随环境复杂度放大。

-   **能力天花板**（β=−0.236, p=0.004）：当单 agent 基线准确率已超过 **~45%**，再加 agent 转为负收益——协调成本超过递减的改进空间。

-   **错误放大依赖拓扑**：Independent（无验证）把 trace 级错误放大 **17.2×**，Centralized（带验证瓶颈）压到 **4.4×**。

-   **性能跨度极大**：相对单 agent 基线，集中式在可并行金融推理上 **+80.8%**，而在顺序规划（Independent）上 **−70.0%**；去中心化在动态网页导航 **+9.2%**（集中式仅 +0.2%）；所有多 agent 变体在顺序约束满足任务上普遍 **−39% ~ −70%**。

-   **冗余是隐形瓶颈**：message density 在约 **0.39 条/轮** 饱和，此后增加消息只带来冗余（redundancy）而非新信息——这正是"扩展收益递减"的微观机制之一。

-   **agent 数量主效应不显著**：决定成败的是结构而非数量；跨模型族外推（GPT-5.2）MAE=0.071，4/5 条缩放定律可泛化。

## 5\. 贡献与创新点

-   首个 agent 系统的**定量缩放定律**，把"是否该用多 agent"从玄学变成可预测、可优化的工程决策。

-   用统一框架反驳了"更多 agent 万能"，给出三条硬规律：45% 法则、工具税、验证瓶颈（错误放大 17×）。

-   把"结构比数量更重要""冗余会吃掉收益"落到可测指标，是 agent harness 设计的方法论基石。

## 6\. 局限与争议 / 后续工作

-   模型只解释约 37% 方差（R²=0.373），仍有大量未捕捉因素。

-   仅测文本 agent，未覆盖多模态；只测 2–4 个 agent 的小团队，未测大规模 swarm。

-   agent 数量主效应不显著，意味着本文主要论证"结构"，对"数量"的缩放曲线刻画有限。

-   后续：与 "When Agents Disagree"（选择瓶颈，arXiv:2603.20324）、"The value of diversity in multi-agent systems"（arXiv:2602.07186）、"Single-Agent Scaling Fails Multi-Agent Intelligence"（arXiv:2512.08743）相互印证"多样性/冗余/选择"才是关键变量。

## 7\. 与 Agent Harness 的关系

对 harness 工程师，本文是最该贴在工位上的"反直觉清单"：**扩展 agent 不是免费午餐，瓶颈常是信息冗余与错误放大，而非协调不够。**

1.  **永远先跑单 agent 基线**：若单 agent 在某任务上已 >45%，加 agent 大概率亏；先优化单 agent 再谈协作。

2.  **加一个集中式验证瓶颈**：无验证的并行架构会把错误放大 17×；用 supervisor/reviewer 在聚合前拦截错误，可压到 4× 量级。

3.  **拓扑匹配任务**：可分解/并行任务用集中式（+80.8%），探索型导航用去中心化，顺序约束任务退回单 agent（多 agent 会 −39%~−70%）。

4.  **压制冗余通信**：消息密度超 ~0.39/轮后增量全是冗余；对广播式通信设上限，按需路由，避免"更多消息 ≠ 更多信息"。
