## 启动时发生的事

1.  创建主 loop，执行初始化操作：

1.  bool looping\_ (当前是否处于循环状态） 初始化为 false
2.  boolquit\_ （是否退出循环标识）初始化为 false
3.  cbool allingPendingFunctors\_ （当前 loop 是否有要执行的回调操作）初始化为 false
4.  int threadId\_ (当前 loop 所在线程id） 初始化为当前线程 id
5.  EPollPoller poller\_ (EPollPoller 实例）初始化：

1.  EventLoop ownerLoop\_ 用传过来的 loop 对该成员变量进行初始化
2.  int epollfd 创建一个 epoll 文件描述符 给 epollfd
3.  std::vector<epoll\_event> events\_ 初始化一个存放 epoll\_event 的 vector

1.  epoll event 是epoll 提供的官方 结构体，定义为 epoll\_event -> struct epoll\_event { uint32\_t event; epoll\_data\_t data;}
2.  epoll\_data\_t typedef union epoll\_data {void \*ptr; int fd; uint32\_t u32; uint64\_t u64;} epoll\_data\_t;
3.  结合上面两个来看，就是 一个 包含 用户指定的指针（这里是 channel）， 对应的 event fd 的东西

6.  int wakeupFd\_ 创建一个用于唤醒的 fd，当 loop 阻塞住时，通过调用它进行写入来唤醒 loop 执行进一步操作
7.  Channel wakeupChannel\_ ， wakeupfd 对应的 channel
8.  wakeupchannel 设置 read 回调：EventLoop::handleRead
9.  从 wakeupfd 的文件中读一个数来唤醒

1.  设置 wakeupchannel 对应的 fd 为可读状态

2.  初始化 EchoServer:

1.  TcpServer server\_：初始化 tcpserver

1.  EventLoop loop\_：主 loop
2.  string ipPort\_：用户设置的 port
3.  string name\_：用户设置的 服务名
4.  std::unique\_ptr<Acceptor> acceptor\_：用 loop, address 初始化一个 acceptor：

1.  EventLoop loop\_：用主 loop 初始化
2.  Socket acceptSocket\_：调用系统 socket 生成对应的 sockfd，并初始化自己定义的 Socket 类（用 sockfd 初始化）

1.  socket 设置地址、端口复用，并绑定地址端口
2.  绑定回调：如果有 新用户链接/read 操作，就执行 Acceptor::handleRead 操作：

1.  如果 accept 有效，获取 客户端 connfd

1.  获取到 connfd 的话，执行上层给的新建立链接时的回调函数 TcpServer::newConnection

1.  轮询选择一个 subloop 来管理新链接 connfd 的 channel
2.  初始化一个 TcpConnectionPtr conn (new TcpConnection)：

1.  初始化 EventLoop loop\_ (子 loop）
2.  初始化 connection 的 name\_
3.  初始化 connedtion 的 state\_ 为 kConnecting
4.  初始化 connection 是否为读状态 reading\_ 为 true
5.  初始化建立一个 socket 是复用的？
6.  初始化一个 channel （子 loop + 传过来的 sockfd）
7.  初始化 highWaterMark\_ 64 M
8.  设置 channel 的 读、写、关闭、异常 回调：
9.  读：TcpConnection::handleRead ， 读是相对服务器而言的 当对端客户端有数据到达 服务器端检测到EPOLLIN 就会触发该fd上的回调 handleRead取读走对端发来的数据。实际上是调用 Buffer inputBuffer\_.readFd 来取走这个 channel 系统 buffer 缓冲区的数据。同时触发用户设置的 onMessage 回调函数
10.  写：TcpConnection::handleWrite，和上面的类似，调用 inputBuffer.writefd 像缓冲区写数据，同时调用用户设置的 writeCompleteCallback 回调函数
11.  关闭：TcpConnection::handleClose， 设置相应的 channel 状态 和 connection 状态。并执行相应的 关闭回调 connectionCallback\_
12.  异常：TcpConnection::handleError

3.  设置 TcpConnectionPtr 的链接、收到消息、写完、关闭链接 对应的回调函数
4.  在 上面被选择的 subloop 下，运行 TcpConnection::connectEstablished 回调：设置 channel 链接状态

3.  Channel acceptChannel：用 sockfd 和 loop 初始化一个 acceptChannel
4.  bool listenning\_：是否在监听，设置为 false

5.  用主 loop 创建一个 EventLoopThreadPool threadPool\_ ：

1.  设置一个 baseLoop
2.  设置 pool 的名称
3.  设置是否启动状态 bool started(false)
4.  设置线程数 ，初始化 0
5.  设置下一个 loop 轮询的下标 的 next\_ 为 0

6.  初始化 connectionCallback
7.  初始化 messageCallback
8.  初始化 下一个链接的 id nextConnId
9.  设置 started\_ 为 0

2.  把主 loop 赋给 EchoServer loop\_
3.  设置用户定义的 server.setConnectionCallback 。。 前面的 connectionCallback
4.  设置用户定义的 server.setMessageCallback。。前面的 messageCallback\_
5.  设置 subloop 数量 server\_.setThreadNum

3.  启动服务：EchoServer server.start() --> TCPServer.start()

1.  EventLopThreadPool -> start(threadInitCallback\_):

1.  根据设置的 subloop 数量，循环生产 EventLoopThread 放到 std::vector<std::uniqueptr<EventLoopThread>> threads\_ 中。std::vector<EventLoop \*> loops 中存放 EventLoopThread::startLoop 返回的 子 loop

2.  loop\_->runInLoop(std::bind(&Acceptor::listen, acceptor\_.get()))：

1.  如果在当前 loop 中执行回调，则直接运行 Acceptor::listen  
    ii.否则把回调函数先存起来，用 wakeup 函数唤醒 loop 所在线程去执行相应的回调

4.  loop 开启事件循环：EventLoop::loop

1.  调用 EPollPoller::poll 获取发生事件的 channel 列表

1.  调用 epoll\_wait 获取发生事件的 epoll\_enent
2.  调用 fillActiveChannels(numEvents, activeChannels) 将 活动的 events\_ 转化为 channel 的 ChannelList \*activeChannels 并返回

2.  对所有发生事件的 channel，执行 Channel:: handleEvent --> Channel:: handleEventWithGuard

1.  针对发生的不同事件类型，执行相应的 callback

## 当有新请求连接时发生的事

1.  accept接收连接， 主 loop 的 epoller-> poll 监听到连接事件 epoll\_event
2.  将该连接epoll\_event 包装成 channel
3.  TcpServer::newConnection通过轮询将TcpConnection对象分配给subloop处理

1.  轮询选择一个 subloop 来管理新链接 connfd 的 channe
2.  初始化一个 TcpConnectionPtr conn (new TcpConnection)：

1.  初始化 EventLoop loop\_ (子 loop）
2.  初始化 connection 的 name\_
3.  初始化 connedtion 的 state\_ 为 kConnecting
4.  初始化 connection 是否为读状态 reading\_ 为 true
5.  初始化建立一个 socket 是复用的？
6.  初始化一个 channel （子 loop + 传过来的 sockfd）
7.  初始化 highWaterMark\_ 64 M
8.  设置 channel 的 读、写、关闭、异常 回调：

1.  读：TcpConnection::handleRead ， 读是相对服务器而言的 当对端客户端有数据到达 服务器端检测到EPOLLIN 就会触发该fd上的回调 handleRead取读走对端发来的数据。实际上是调用 Buffer inputBuffer\_.readFd 来取走这个 channel 系统 buffer 缓冲区的数据。同时触发用户设置的 onMessage 回调函数
2.  写：TcpConnection::handleWrite，和上面的类似，调用 inputBuffer.writefd 像缓冲区写数据，同时调用用户设置的 writeCompleteCallback 回调函数
3.  关闭：TcpConnection::handleClose， 设置相应的 channel 状态 和 connection 状态。并执行相应的 关闭回调 connectionCallback\_
4.  异常：TcpConnection::handleError

3.  设置 TcpConnectionPtr 的链接、收到消息、写完、关闭链接 对应的回调函数
4.  在 上面被选择的 subloop 下，运行 TcpConnection::connectEstablished 回调：设置 channel 链接状态

4.  subloop运行 runInLoop:

1.  loop\_->runInLoop(std::bind(&Acceptor::listen, acceptor\_.get()))：

1.  如果在当前 loop 中执行回调，则直接运行 Acceptor::listen
2.  否则把回调函数先存起来，用 wakeup 函数唤醒 loop 所在线程去执行相应的回调
