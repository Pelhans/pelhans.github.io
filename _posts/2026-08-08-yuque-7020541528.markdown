# 模块定位

与地图搜索对比，消歧层是地址识别的特殊模块，主要解决美团大搜多业务场景下的强歧义Query误识别问题。例如"卸甲"、"肤乐霜"等，由于App定位以及供给情况，这一类Query更应该给用户返回"卸甲服务"以及商品，而不是"卸甲村"、"肤乐霜医院"地址周边的POI。

难点与挑战：

a. 地址属于怎么搜，其他业务属于要什么，因此不能从意图层进行区分；

b. 商品和服务类数据无感知、增量式接入，供给变化会影响识别结果；

![image.png](/img/yuque/NEXT/3._地标业务/1._地标信号识别/assets/1.5_地标业务消岐_+_各业务适配-1.png)

总结下来，该模块需要完成以下三种功能。

-   Query 意图判别：

-   结合地标召回结果以及 Query 意图分数进行过滤

-   NIL 判别：

-   根据文本、语义、点击相关性信息，判断 query 与top1 结果的匹配程度，如不满足要求，则认为当前 query 是不可链接的

-   Top1 结果可展示性判别：

-   根据 poi 质量、poi 类型、产品形态要求等情况，判断top1 结果是否需要进行主点展示以及展示样式

## 特征挖掘

大体上分为：

1.  query 本身意图特征（用的 squirrel 缓存，在线读取 query 的打分缓存）
2.  query 的字符特征（长度，是否包含特定 pattern）、NER 是否包含地址成分、where-what 是否包含地址成分、where 是否在开头、where是否在结尾、where打分、what 打分
3.  query 的行为特征：点击率、换词率、访购率、点击意图分布
4.  商家供给检索情况：query 被各种供给的包含情况（每种供给不丢词的召回数量，连续 n-gram 的包含比例）。。。where 被各种供给的包含情况
5.  当前qeury 被识别成地标的次数、qv、全国被搜索的城市个数

## 地标意图判别模型

当做消岐的语义特征。

### 训练数据

线上根据规则采样，而后通过外包标注得到质量较高的样本。外包主要标 query 中是否包含地址成分。外包标了10w 条数据，一周2w 条，准确率 96% 以上。

1.  NER 中包含地址成分
2.  where-what 有地址成分
3.  线上随机采样

负例：

1.  商户、商品等供给
2.  正例标注过程中得到的负例

### 特征构造：

1.  query
2.  城市名称
3.  query 的字符特征（长度，是否包含特定 pattern）、NER 是否包含地址成分、where-what 是否包含地址成分、where 是否在开头、where是否在结尾、where打分、what 打分

​  

将 query 和 where 拼接输入 BERT 模型，而后将 BERT 模型的 CLS 输出和其他特征进行拼接，送入 FN 层，进行分类。

### 效果

测试集：eval\_AUC = 0.99793327 eval\_accuracy = 0.98129165 eval\_fscore = 0.98134 eval\_precision = 0.97880983 eval\_recall = 0.9838833

挖掘query：eval\_AUC = 0.87289625 eval\_accuracy = 0.8065699 eval\_fscore = 0.80100596 eval\_precision = 0.79476506 eval\_recall = 0.8073456

人工标注：eval\_AUC = 0.84727645 eval\_accuracy = 0.80786115 eval\_fscore = 0.62616456 eval\_precision = 0.5522081 eval\_recall = 0.72299415

badcase：eval\_AUC = 0.7874874 eval\_accuracy = 0.72289157 eval\_fscore = 0.7356322 eval\_precision = 0.7032967 eval\_recall = 0.7710843

​  

总结：训练数据上，f1 98.4%， 人工标注数据集上， f1 84%（和上面的关联不上）。
