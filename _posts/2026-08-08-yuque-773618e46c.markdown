# 论文解读：GAIA: A Benchmark for General AI Assistants（2023）

> 一句话总结：GAIA 用 466 个"对人类简单、对 AI 极难"的真实助手任务（推理+多模态+网页浏览+工具使用）建立通用 AI 助手基准，揭示顶尖模型通过率不足 40%、而人类高达 92% 的能力鸿沟。

## 1\. 背景与动机

2023 年前后，LLM 评测陷入两个误区：一是不断把基准推向"对人类更难"的方向（如 MMLU、GSM8K、各类 STEM/法律考试），但这些题正被快速饱和且易数据污染；二是评测多为静态、单轮、纯文本，无法反映真实助手要"在不确定世界中多步行动"的本质。作者（Meta-FAIR、HuggingFace、AutoGPT、Meta-GenAI）指出：AGI 的标志不是考过专业考试，而是像普通人一样稳健地完成日常任务。于是 GAIA 反其道而行——刻意选取"概念简单但对 AI 极具挑战"的任务，要求模型组合推理、多模态理解、网页浏览与工具调用来给出唯一可验证的事实性答案。

## 2\. 核心问题

GAIA 试图回答：(1) 当前 LLM/agent 在需要多步工具使用的真实助手任务上到底有多弱？(2) 能否构建一个"答案易验证、难记忆、抗污染"的评测，避免传统基准的饱和与 gaming？(3) 人类与 SOTA 系统之间的差距能否量化成一个清晰的里程碑指标？

## 3\. 方法与架构

GAIA 由人类设计、双重标注校验，共 **466 个问题**，附带文件（图像、表格等）作为 evidence。问题按难度分三级：

-   **Level 1**：<5 步、几乎无需工具（单源查找）；

-   **Level 2**：5–10 步、需协调多种工具（跨源交叉验证）；

-   **Level 3**：10+ 步、任意工具链、长程规划与多模态输入。

评测协议极其简单：零样本把问题+evidence 交给助手，产出最终答案，采用\*\*精确匹配（binary、无部分分）\*\*自动打分——答案错一个数量级即判失败，类似 Proof-of-Work：难解易验。其中 166 题带答案发布为 dev 集，另 300 题隐藏答案用于排行榜。这种"小样本+唯一答案+真实时检索"的设计天然抗训练数据污染。

## 4\. 关键实验与结论

-   **人类准确率 92%**，而 **GPT-4 配插件仅 15%**——这是论文最常被引用的数字，凸显约 77 个点的真实能力鸿沟。

-   难度分层明显：GPT-4 在最易的 Level 1 约 30%，Level 2 约 10%，**Level 3 通过率接近 0%**。

-   后续两年进展迅速但仍远未饱和：2024 年 Microsoft（o1）约 41%、Google Langfun 约 49%、H2O.ai 达 65%；到 2025–2026 年头部系统爬升至约 75%–86%（如 Manus、天工等），但剩余 15–25 个点被社区认为是"全 AI 评测中最难的部分"。

## 5\. 贡献与创新点

相对前人的增量：(1) 范式反转——从"考人类难"转向"考 AI 真实易错"，更贴近助手落地；(2) 把工具使用、网页浏览、多模态、长程推理压缩进单一可验证任务，首次系统化评测"通用 agent 能力"而非单技能；(3) 用 binary scoring + 真实时检索天然抗污染与 gaming，成为后续 agent 基准（见下）的方法论母本。

## 6\. 局限与争议 / 后续工作

已知短板：仅英文、缺乏语言/文化多样性；只验证单一正确答案，无法容纳多解或现实歧义；不测延迟、成本与检索幻觉率。后续重要跟进：更垂直的 agent 基准 **WebArena**（网页导航）、**OSWorld**（真实 OS 上 369 个跨应用 GUI 任务）、**τ-bench**（工具-用户交互的客户服务体系列）、**AgentBench**（多环境综合），以及 GAIA 自身的 2.0 规划。SWE-bench 也继承了"真实任务+可执行验证"的思路。

## 7\. 与 Agent Harness 的关系

构建 agent harness 时，GAIA 给出三条直接启示：

1.  **harness 的成败在工具编排，不在模型本身**：15%→65% 的跃迁主要来自更好的工具接入与决策循环（如 H2O 用单一 agent + 代码优先 + 最小脚手架），而非换更大模型。避免过早为上模型能力过度搭脚手架。

2.  **把"可执行验证"作为评测第一原则**：用 binary、无部分分的真实任务衡量 harness，比人工/模型打分更稳健，应内置到回归测试。

3.  **分级压测 harness**：用 Level 1/2/3 对应"单工具/多工具协调/长程多模态规划"，逐层暴露检索、工具调用与规划各自的瓶颈。
